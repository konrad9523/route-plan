## 口径

| 项 | 设置 |
|---|---|
| 路网 | 南山区 13,357 节点；深圳市 85,709；广东省 1,072,749（230 万条边） |
| OD | 100 对与 1000 对，按最短路长度分短/中/长（1000 对为 333/333/334） |
| 重复 | 3 次取平均 |
| 种子 | 20261102 |
| 基准 | 每条 OD 单独跑一次 Dijkstra，逐个算法比对 `cost` |
| 缓存 | 全部命中；预处理取缓存首次构建记录 |

## 1000 对结果

| 算法 | 南山区 | 深圳市 | 广东省 | 广东扩展节点 | 广东 P95 |
|---|---|---|---|---|---|
| Dijkstra | 0.782 ms | 6.792 ms | 123.599 ms | 523,543 | 225.0 ms |
| A* | 0.361 ms | 2.644 ms | 63.859 ms | 178,134 | 220.5 ms |
| 双向 A* | 0.275 ms | 2.105 ms | 66.520 ms | 152,936 | 190.6 ms |
| CH | 0.035 ms | 0.196 ms | 2.157 ms | 2,289 | 3.5 ms |

累计成本（预处理 + 1000 次查询）：

| 算法 | 南山区 | 深圳市 | 广东省 |
|---|---|---|---|
| Dijkstra | 781.6 ms | 6,791.6 ms | 123,599 ms |
| A* | 364.1 ms | 2,651.5 ms | 64,043 ms |
| 双向 A* | 278.6 ms | 2,134.8 ms | 67,093 ms |
| CH | 196.4 ms | 2,859.9 ms | 130,261 ms |

## 三条结论

1. **单次查询 CH 全胜**：广东 2.16 ms，约 Dijkstra 的 1/57；代价是 128 s 预处理、172 MB 索引。
2. **非 CH 方案**：南山、深圳选双向 A*；广东选 A*——双向 A* 扩展少 14% 却慢 4%。
3. **是否上 CH 看查询量**：回本点约为南山 658 次、深圳 1,380 次、广东 2,074 次。
