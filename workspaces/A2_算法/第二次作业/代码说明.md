# 代码说明

这份文档说明 `第二次作业/` 里每个代码文件是做什么的、一次测试怎么跑起来，以及为什么 C++ 会分成几个文件。

---

## 一、顶层目录

```text
第二次作业/
├── 算法/            # 四个 .cpp + 两个 .hpp
├── 接口/            # 测试与接口系统：调度、缓存、计时、出图、HTTP
├── 结果/            # 6 组归档结果（self_test/）
├── 报告/            # 3 份 docx
└── AI使用说明/      # AI 日志
```

**算法代码**只有 `算法/`；**测试代码**是 `接口/`。两者分开，改算法不影响测试器，改测试器也不碰算法。

---

## 二、`算法/` 四个文件

| 文件 | 作用 |
|---|---|
| `dijkstra.cpp` | Dijkstra，正确性基准；测试器用它逐条校验其他算法的 `cost` |
| `astar.cpp` | A*，Haversine 启发 + 安全比例 α |
| `bidirectional_astar.cpp` | 双向 A*，反向索引 + 平衡势 + 三维弦长 |
| `ch.cpp` | Contraction Hierarchies，预处理 + 双向上坡查询 |

四个文件都只 `#include "algorithms.hpp"`，不包含 `main`，由测试器调用。

## 三、`算法/` 里的两个头文件

| 文件 | 作用 |
|---|---|
| `algorithms.hpp` | 四个算法的对外函数：`dijkstra` / `astar` / `prepare_bidirectional_astar` / `preprocess_ch` / `ContractionHierarchy::query` |
| `graph_types.hpp` | `RoadGraph`（出边、坐标）、`Edge`、`PathResult`、`QueueItem` 等公共类型 |

---

## 四、`接口/` 里每个文件

| 文件 | 作用 |
|---|---|
| `api.py` | **全部 Python 逻辑**：9 个 HTTP 路由、缓存管理、调用 C++ 测试器、生成图表、自测界面、命令行入口 |
| `config.json` | 数据集清单（`nanshan` / `shenzhen` / `guangdong`）、A1 路网路径、输出目录、默认参数、缓存格式版本 |
| `接口说明.md` | 前端契约：9 个端点、参数、返回字段、错误码 |
| `requirements.txt` | FastAPI、Uvicorn、Matplotlib |
| `assets/` | 中文字体说明和 OFL 许可证（字体文件不入库） |
| `cpp/` | C++ 测试器源码，编译成 `route_benchmark.exe`；`runtime/`（build / cache / queries）首次运行时自动生成，不在包内 |

`api.py` 自带命令行入口（`--prepare` / `--serve` / `--gui`），不再需要 bat 文件。

`api.py` 内部按顺序分成八段：配置与路径 → GraphML 转 RGRAPH → 缓存管理 → 出图 → 测试执行 → 9 个 HTTP 路由 → 自测界面 → 命令行入口。

---

## 五、`接口/cpp/` 四个代码文件

| 文件 | 规模 | 职责 |
|---|---|---|
| `benchmark_main.cpp` | 约 1,500 行 | **主程序**：解析参数 → 读路网 → 建/读缓存 → 对每组 OD 跑选中的算法 → 用 Dijkstra 校验 `cost` → 写 `preprocess_summary.csv`、`query_raw.csv`、`summary.json` → 打印 `PROGRESS` 给 Python 读进度 |
| `rgraph_io.cpp` + `.hpp` | 约 60 行 | **读路网**：把 `graph.rgraph` 读成 `RoadGraph`（节点坐标、出边、边权、边 ID） |
| `cache_io.cpp` + `.hpp` | 约 250 行 | **读写三种算法缓存**：A* 的 α、双向 A* 的反向索引、CH 的层次与 shortcut，分别存成 `astar.cache`、`bidirectional_astar.cache`、`ch.cache` |
| `query_io.cpp` + `.hpp` | 约 180 行 | **读写 OD**：按距离分档（短/中/长）生成固定起终点，存成 `nan_shan_Q1000_S20261102.csv` 这类文件，下次复用 |
| `CMakeLists.txt` | 37 行 | 编译配置：四个 `.cpp` + `算法/` 四个算法 → 一个 `route_benchmark.exe` |

调用关系：

```text
benchmark_main.cpp
   ├── rgraph_io   读 graph.rgraph
   ├── query_io    生成 / 读 OD csv
   ├── cache_io    读 / 写三种 .cache
   └── 算法/        dijkstra / astar / bidirectional_astar / ch
```

---

## 六、一次测试怎么跑

1. `api.py` 把 A1 的 GraphML 转成 `graph.rgraph`；
2. `benchmark_main` 读 `graph.rgraph`；
3. 首次运行时预处理：A* 算 α、双向 A* 建反向表、CH 收缩建 shortcut，分别写进三个 `.cache`；
4. 生成或读取固定 OD（`runtime/queries/*.csv`）；
5. 对每组 OD、每个算法跑 `repeat` 次，记录耗时、扩展节点、入队次数；
6. 每条 OD 额外跑一次 Dijkstra 做基准，比对 `cost`；
7. 输出 `query_raw.csv`、`summary.json`、`preprocess_summary.csv`；
8. `api.py` 读这些文件，生成 `algorithm_summary.csv` 和 2×2 的 PNG；
9. 前端通过 9 个接口读取结果。

---

## 七、为什么 C++ 不是一个文件

A3 的 `performance_comparison.cpp` 只有一个文件，因为它只做“跑性能对比”：自己加载图、调算法、统计，CH 索引也由它现建。它不需要把 A*、双向 A*、CH 的索引持久化成三种缓存文件。

这里多出来的三个 IO 文件，对应三类**二进制格式**：

- `graph.rgraph`：路网；
- `*.cache`：三种算法各自的索引，格式互不通用；
- `queries.csv`：固定 OD。

如果全部塞进 `benchmark_main.cpp`，主程序会变成 2,000 行左右，格式读写和调度混在一起，改缓存格式时容易碰坏主流程。所以按“主程序 + 三类格式读写”拆开，每个文件只做一件事。

想再合并的话，合理做法是把 `rgraph_io` / `cache_io` / `query_io` 合成一个 `io.cpp`（约 500 行），`benchmark_main.cpp` 保持独立；不建议把 1,500 行主程序和格式读写塞进同一个文件。

---

## 八、这个包里有没有单元测试

没有 pytest 之类的测试文件。正确性是在测试器里**逐条 OD 和 Dijkstra 对拍**完成的：每条 OD 都跑一次 Dijkstra 作为基准，四个算法的 `cost` 必须一致，结果写进 `summary.json` 的 `validation.mismatch_count`（三个路网全为 0）。
