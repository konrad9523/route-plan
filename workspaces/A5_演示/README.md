## 一、我这个角色负责什么

| 职责 | 说明 |
|---|---|
| **PPT 与演示材料** | 四次汇报与最终答辩的幻灯片、讲稿、演示脚本 |

**职责边界（重要）**：

| 我做 | 我不做 |
|---|---|
| 出 PPT、讲稿、演示方案 | 写前端代码（A4 负责） |
| 给前端提供视觉/交互建议 | 改 `/web/` 下的实现 |
| 收集各角色的图表与截图 | 自己产出实验数据（A1~A4 负责） |
| 组织答辩演练 | 改 `/web/` 下的实现（A4 负责） |
| 收集各角色的图表与截图 | 自己产出实验数据（A1~A4 负责） |
| 核对素材里的数字与来源 | 承担测试职责（见下方说明） |

> **测试职责的准确范围见** [`团队协作与项目管理原则.md`](../../docs/operations/团队协作与项目管理原则.md) **§3.3.1**：
> **每位代码作者验证自己的改动**，任何成员都可以跑测试；
> A3 负责**测试策略、集成回归与性能基准**。
> A5 **不承担测试职责**，但**可以运行测试**——
> 演示材料里的每个数字都应能追溯到来源与验证方式。

### 01_PPT与讲稿

按汇报批次组织：

| 文件 | 对应 | 状态 |
|---|---|---|
| `汇报1_基础实现.md` | 第 4 周 | 待填 |
| `汇报2_算法进阶.md` | 第 7 周 | 待填 |
| `汇报3_功能深入.md` | 第 10 周 | 待填 |
| `汇报4_完整系统.md` | 第 12 周 | 待填 |
| `最终答辩.md` | 答辩 | 待填 |
| `演示视频脚本.md` | 3–5 分钟视频 | 待填 |

**每份演示材料至少包含**：

| 项 | 说明 |
|---|---|
| 演示顺序 | 一步一步的操作与讲解 |
| 讲解词 | 每页说什么、强调什么 |
| 时间预算 | 总时长与各段时长 |
| **预判提问** | 老师可能问什么、怎么答 |
| **失败备用方案** | 某个功能现场崩了改看什么（截图/录屏） |

> **答辩有 15% 是"核心函数解释"**，要求每个人能讲清自己模块的核心函数。
> 所以 PPT 里要为**每个角色**留一页"你的核心代码在做什么"，并提前向本人收集讲解要点。

### 02_视觉设计

给 A4 的**建议**（不是实现）：

- 配色方案（三层状态用什么颜色、对比度是否足够）
- 界面布局建议（控制面板放哪、信息层级）
- 图表形式建议（性能对比用对数坐标还是柱状图）
- 可用性检查（按钮是否够大、错误提示是否清楚）

格式可以是文字说明 + 参考图，交给 A4 在 `/web/` 里实现。
