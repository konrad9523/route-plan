## 一、我这个角色负责什么

| 地图与交互 | 点击选起终点、路线绘制、多路线叠加 |

**这个角色的特殊之处**：成果**必须能被"看"到**。所以截图和演示脚本的价值高于代码说明。

## 三、本区结构

```text
workspaces/A4_交互/
├── README.md            # 本文件：职责 + 索引 + 状态
├── 01_界面说明/          # 每个页面：功能、操作步骤、依赖什么数据
├── 02_效果截图/          # 静态图（截图是最有效的成果证明）
└── 03_演示脚本/          # 演示顺序、讲解词、失败时的备用方案
```

### 01_界面说明

每个页面一个文件，命名如 `搜索动画.md`。**必须包含**：

| 项 | 示例 |
|---|---|
| 页面名称与用途 | 搜索过程可视化 · 作业 1 主演示 |
| 启动方式 | `python -m uvicorn api.main:app --port 8077`，浏览器打开 `http://127.0.0.1:8077` |
| 依赖的后端接口 | `/api/meta`、`/api/nodes`、`/api/route` |
| 操作步骤 | ① 点地图选起点 → ② 再点选终点 → ③ 点"开始" → ④ 点"播放"看动画 |
| 三个图层含义 | 深灰=已访问 · 橙=边界（待扩展） · 绿=最终路径 |
| 依赖的数据字段 | `trace.pop_order`、`trace.discovered_order`、`trace.discovered_after_steps` |
| 已知限制 | 大图需降采样（`max_steps`）；底图需联网加载 OSM 瓦片 |

### 02_效果截图

| 要求 | 说明 |
|---|---|
| 命名 | 场景_状态.png，如 `搜索动画_进行中.png` |
| 内容 | 要能体现**功能**，不只是好看 |
| 建议必拍 | 搜索动画三个时刻（早期/中期/完成）、多路径对比、仪表盘、导航演示 |

**截图是成果证明**。作业 4 的演示视频、答辩 PPT 都要从这里取材。

### 03_演示脚本

| 项 | 说明 |
|---|---|
| 演示顺序 | 一步一步写清点什么、说什么 |
| 讲解词 | 每个界面讲什么、强调什么 |
| 时间预算 | 总时长与各段时长 |
| **失败备用方案** | 某个功能现场崩了，改看什么（截图/视频） |
