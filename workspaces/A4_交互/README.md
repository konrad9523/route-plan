### ⚠️ 关于"前端源代码"目录

本区设 `00_前端源代码/` 作为**源码索引**，但**代码本体仍在 `/web/`**。原因是本项目已确立的防重复规则：

> **同一个文件只能有一个正式位置。**（见管理原则文件第 2、3 节）

**如果两端各放一份代码，会出现**：

| 问题 | 后果 |
|---|---|
| 两份代码不同步 | 评审时不知道该看哪份，改了一处另一处过期 |
| 代码审查失效 | PR 只改 `/web/`，成果区那份静默变旧 |
| 答辩时说不清 | 老师问"这份代码是最新的吗"，无法给出确定答案 |

**所以本区的 `00_前端源代码/` 放**：

- 源码结构说明（哪个文件负责什么）
- 与后端的接口依赖（用了 `SearchTrace` 的哪些字段）
- 运行与构建方式
- **指向 `/web/` 的相对链接**

**如果你的意图确实是"要在成果区看到代码文件本身"**，那么应该改的是规则而不是加副本——
即把前端源码的**正式位置**定为 `workspaces/A4_交互/00_前端源代码/`，同时删除 `/web/`。
这需要先和全组确认，因为它影响构建路径、API 静态目录配置和部署脚本。**在确认前，本区只放索引。**

```text
└── 05_AI使用说明/          # 用 AI 做了什么、怎么验证的、发现了什么问题
```

### 01_界面说明

每个页面一个文件，命名如 `搜索动画.md`。**必须包含**：

| 项 | 示例 |
|---|---|
| 页面名称与用途 | 搜索过程可视化 · 作业 1 主演示 |
| 启动方式 | `python -m uvicorn api.main:app --port 8077`，浏览器打开 `http://127.0.0.1:8077` |
| 依赖的后端接口 | `/api/meta`、`/api/nodes`、`/api/route` |
| 操作步骤 | ① 点地图选起点 → ② 再点选终点 → ③ 点"开始" → ④ 点"播放"看动画 |
| 三个图层含义 | 深灰=已访问 · 橙=边界（待扩展） · 绿=最终路径 |
| 依赖的数据字段 | `trace.pop_order`、`trace.discovered_order`、`trace.discovered_after_steps` |
| 已知限制 | 大图需降采样（`max_steps`）；底图需联网加载 OSM 瓦片 |

### 03_可视化结果

| 要求 | 说明 |
|---|---|
| 命名 | `场景_状态.png`，如 `搜索动画_进行中.png` |
| 内容 | 要能体现**功能**，不只是好看 |
| 建议必录 | 搜索动画三个时刻（早期/中期/完成）、多路径对比、仪表盘、导航演示 |
| 录屏 | 需要联网加载底图时，录屏比截图更能证明流畅度 |

**这些是成果证明**。作业 4 的演示视频、答辩 PPT（A5 负责）都要从这里取材。
