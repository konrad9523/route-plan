车辆导航可视化系统使用说明

一、启动
1. 保持 index.html、app.js、styles.css、server.py、start-server.bat、assets 和 data 文件夹的相对位置不变。
2. Windows 用户双击 start-server.bat；它会依次检查/启动 A2（8000）、A3（8100）和网页服务（5173）。
3. 浏览器打开 http://localhost:5173/
4. 不建议只运行 py server.py，因为这样 A3 性能板块没有 8100 服务。

不要直接双击 index.html。页面需要通过本地 HTTP 服务访问后端接口和 SQLite 路网。

二、A4 导航
1. A4 导航固定使用 dataset=guangdong，对应 data\server\guangdong-roads.sqlite。
2. 在地图上第一次点击设置起点，第二次点击设置终点；点击位置会在路线请求时吸附到最近道路节点。
3. 点击“路线”后，服务端计算路径并返回搜索轨迹与最终路径，前端负责动画显示。
   无约束路线使用 A3 的 C++ 优化后端：Dijkstra L4、A* L4、双向 A* B1 和 CH。
   启动服务时会预加载广东路网，避免用户点击路线时等待整图导入；后续查询会复用内存图。CH 使用随桌面包提供的预处理缓存，不会在点击路线时现场构建。
   如果选择其他路线目标或打开避让/拥堵约束，会使用兼容约束逻辑的 Python 后端。
4. 搜索时不绘制完整路网，只显示遍历折点、候选边界折点和当前折点；完成后显示最终路线。
5. 右侧路线摘要可以关闭，已完成的路线会保留在搜索框下方的历史记录中；点击记录可再次展开。
6. “底图压暗”保留在主界面；CH 收缩和模拟拥堵位于“拓展功能”。“预计用时”不属于当前界面功能，未恢复。

三、算法成果
1. 点击“算法成果”打开独立板块。
2. A2 基础版横向对比支持广东省、深圳市、南山区等测试尺度，并提供与 A2 接口一致的参数设置。
3. A3 最新接口支持选择路网尺度、查询数（1–100）、算法、重复轮数（1–5）和随机种子；结果展示五种最终算法配置的 p50、Q1–Q3、平均扩展节点及相对 Dijkstra 加速比。
4. CH 预处理回放展示节点收缩和捷径边事件。
5. A2/A3 接口未启动时，性能板块会提示不可用，不影响 A4 导航。A3 会复用已有缓存；桌面包启动时会自动准备 CH 缓存。

四、服务接口
GET /api/health       查看服务和数据集状态
GET /api/datasets     查看三套数据集的名称、规模和范围
POST /api/route       提交起点、终点、算法和路线选项

A3 服务接口（http://127.0.0.1:8100/api/benchmark）：
GET /datasets         查看三套测试路网
POST /run             提交 A3 测试任务
GET /jobs/{job_id}    查询任务状态和结果
GET /summary?dataset= 查询最近一次结果

当前 A4 导航不再使用旧的 /api/network 地图框选接口，也不使用武汉 JSON、Overpass 或在线 OSM 路网回退。武汉历史文件若仍在 data 目录，仅作为资料保留，不参与运行。

五、数据文件
data\server\guangdong-roads.sqlite  广东省，A4 默认使用
data\server\shenzhen-roads.sqlite   深圳市，A2/A3 性能测试
data\server\nanshan-roads.sqlite     南山区，A2/A3 性能测试

SQLite 是服务器内部的数据文件，用户不需要打开、编辑或选择。服务端第一次使用某套路网时加载并缓存图结构，后续请求复用缓存。大文件请按团队约定使用 Git LFS、Release 附件或单独数据包共享，不要通过 GitHub 网页直接上传。

六、数据来源
路网数据来源于 OpenStreetMap。重新分发时请保留来源、下载时间、范围和 ODbL 许可信息。
