# 华盛顿 OSM 路网字段与单位说明

## 1. 数据概况

数据名称：华盛顿特区 OSM 机动车有向路网

原始数据：district-of-columbia-261011.osm.pbf

数据格式：GraphML

路网结构：有向图，节点表示道路连接位置，边表示允许通行方向上的道路路段。

数据来源：OpenStreetMap（OSM）。

坐标系：WGS84 经纬度坐标（EPSG:4326）。

数据经过机动车道路筛选、方向识别、道路分段和几何计算后生成，适用于项目中的路网加载与路径规划实验。

## 2. 节点字段

| 字段 | 类型 | 单位 | 含义 |
|---|---|---|---|
| id | 字符串形式的节点编号 | 无 | GraphML 节点标识，来源于 OSM Node ID |
| x | double | 十进制度（°） | WGS84 经度，东经为正 |
| y | double | 十进制度（°） | WGS84 纬度，北纬为正 |

说明：

1. 节点 ID 是标识符，不表示距离或空间顺序。
2. `x`、`y` 分别对应经度和纬度，不能直接将经纬度差作为米制距离。
3. 非路由连接点的部分中间形状点仅保留在边的 `geometry` 中，不单独建立 GraphML 节点。

## 3. 边字段

| 字段 | 类型 | 单位 | 含义 |
|---|---|---|---|
| id | 字符串形式的边编号 | 无 | GraphML 边标识 |
| source | 节点编号 | 无 | 有向边起点 |
| target | 节点编号 | 无 | 有向边终点 |
| length | double | m | 沿道路几何折线累计计算的长度 |
| speed_kph | double | km/h | 用于路径规划的道路速度 |
| highway | string | 无 | OSM 道路类型 |
| geometry | string | WGS84 经纬度 | 道路形状，使用 WKT LINESTRING |
| name | string | 无 | 道路名称，可能为空 |
| toll | string | 无 | 收费属性，当前输出采用 yes/no 表示 |

GraphML 使用 `edgedefault="directed"`，即每条边具有明确的方向。

对于允许双向通行的道路，转换器通常分别生成两个方向的有向边；单向道路仅生成允许方向的边。

## 4. 主要字段计算与处理规则

### 4.1 道路长度

`length` 使用道路几何中相邻坐标点之间的球面距离累计得到，单位为米。

距离计算采用 Haversine 公式，球体半径取 6371008.8 m。

因此，`length` 是基于 OSM 几何得到的近似道路长度，不等于实际车辆行驶里程或测量实测值。

### 4.2 道路速度

`speed_kph` 优先从可解析的 OSM `maxspeed` 标签获取。

当原始限速缺失、格式不支持或数值不符合程序设定范围时，使用按 `highway` 道路类型设置的默认速度。

该字段是路径规划使用的计算参数，不保证等于实时车速或现场实测限速。

旧版 GraphML 未单独保存原始 `maxspeed` 字符串或默认速度来源标记；A1-5 最终版本已新增对应的可追溯字段。

### 4.3 通行时间

使用道路长度和速度估计通行时间：

`t = length / (speed_kph / 3.6)`

其中：

- `length` 单位为 m；
- `speed_kph` 单位为 km/h；
- `t` 单位为 s。

该结果属于静态估计，不包含实时拥堵、信号灯等待和实际驾驶行为等因素。

### 4.4 道路方向

转换时根据 `oneway`、`junction` 和部分道路类型标签识别允许通行方向。

对于部分可变方向道路，现有程序采用排除或简化处理。

道路网络保留 OSM 数据中的方向信息，但不代表全部现实交通规则均已完整建模。

## 5. 数据限制与使用注意事项

1. 原始 OSM 数据可能存在信息缺失或更新滞后。
2. `speed_kph` 部分使用默认速度，最快路径结果依赖这些速度假设。
3. 当前路网转换未完整应用 OSM Relation 中的转向限制。
4. 条件性通行、车道级限制等复杂规则未完整实现。
5. 部分合法闭合道路可能形成自环或由多个有向边构成回路，不能仅因起终点相同就判定为错误。
6. `toll` 是 GraphML 中的字符串，加载到项目内部布尔属性时，应正确解析 yes/no。
7. GraphML 边编号是转换输出编号，当前版本未提供独立的 OSM Way ID 字段，不能直接通过边编号追溯原始 Way。

## 6. 验证说明

本数据使用项目路网质量验证程序检查节点、边、属性、几何、连通性和路径规划结果。

A1-1、A1-2 修复过程中，还进行了原有边集合比较、闭合道路专项验证、权限规则全量扫描和 Dijkstra/A* 路径抽样回归。

最终提交版本的节点数、边数和验证报告应以该版本实际运行输出为准，不应混用不同修复阶段的数据统计。
## 7. A1-5 最终版本新增字段

A1-5 修复后的华盛顿路网新增以下边属性：

| 字段 | GraphML 类型 | 含义 |
|---|---|---|
| osmid | string | 原始 OSM Way ID，同一 Way 拆分后的边保留对应来源 ID |
| maxspeed_raw | string | 原始 OSM maxspeed 标签，缺失时为空字符串 |
| speed_source | string | 速度计算来源，取值为 osm_maxspeed 或 default |

其中，osm_maxspeed 表示原始限速成功解析，default 表示采用道路类型默认速度。存在原始 maxspeed 标签并不一定意味着成功解析。

最终验收路网包含 41,679 个节点、99,543 条有向边。所有边的新增字段均通过原始 PBF 来源核验，原有节点、道路方向、长度、速度及几何与 A1-2 基准保持一致。
