# 华盛顿与深圳路网成果主仓库归档建议

## 1. 说明目的

A1 数据线已完成华盛顿特区和深圳市 OSM 机动车路网的处理与基础质量验证，相关成果目前统一存放于 `workspaces/A1_数据/`。

为方便后续各模块集成，现说明各类成果在主仓库公共目录中的建议归档位置。本说明仅提供文件归档和接口对接建议，不代表已经完成公共目录迁移。

## 2. 建议归档位置

| 成果类别 | 建议归档目录 | 具体文件 |
|---|---|---|
| 正式路网数据 | `data/processed/` | `dc_driving_optimized.graphml`、`shenzhen_driving_optimized.graphml` |
| 原始路网数据 | `data/raw/` | `district-of-columbia-261011.osm.pbf` |

| 转换与验证脚本 | `tools/` | `inspect_osm.py`、`convert_dc_osm.py`、`convert_dc_osm_optimized.py`、`validate_dc_network.py` |
| 处理技术文档 | `docs/development/` | 华盛顿、深圳两份路网处理与验证说明 |
| 字段及接口说明 | 由团队确认统一文档位置 | A1 已提交的字段与接口说明 |
| AI 使用声明 | `workspaces/A1_数据/06_AI使用说明/` | 已提交的 AI 使用说明 |

## 3. 对其他模块的影响

两份 GraphML 均采用现有路径规划项目可读取的有向图数据格式。

- **A2 算法组**：可使用现有 `load_graphml()` 加载路网，测试 Dijkstra、A* 等算法。
- **A3 测试组**：可使用质量验证结果进行数据检查、性能测试与规模比较。
- **A4 前端组**：可以读取节点经纬度及道路几何，后续进行城市级路网可视化适配。
- **A5 汇报组**：可引用数据规模、来源及验证结果。

## 4. 集成注意事项

1. 当前两座城市的数据已在 A1 工作区保存，正式集成时应采用单一正式路径，避免同一份大文件重复存储。
2. 如果更改 GraphML 的存放位置，需要同步更新相关程序的读取路径及文档。
3. 本次 A1 成果不包含公共 API、前端和核心算法代码修改。
4. 正式迁移前应由相关模块负责人确认目录和接口约定。

因此，建议目前保留 A1 工作区中的原始提交，在团队确认后，再通过独立 PR 完成公共目录集成。
