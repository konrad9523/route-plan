# 华盛顿与深圳路网成果主仓库归档建议

## 1. 说明目的

A1 数据线已完成华盛顿特区和深圳市 OSM 机动车路网处理、质量验证及 A1-1～A1-6 修复。当前成果主要位于 `workspaces/A1_数据/`，其中 A1-6 涉及的共用加载器位于 `src/path_planning/osm_loader.py`。

## 4. 对其他模块的影响

两份 GraphML 均采用项目能够读取的有向路网格式。

- **A2 算法组**：可使用 `load_graphml()` 加载最终路网，测试 Dijkstra、A* 等路径规划功能；A1-6 已修复 `toll` 字段加载，避收费策略采用惩罚而非绝对禁止。
- **A3 测试组**：可使用 `docs/validation/` 下的质量验证和 A1 专项测试证据进行规模、属性、连通性、复现与性能检查。
- **A4 前端组**：可读取节点经纬度和道路 `geometry`，进行路网可视化适配；迁移后需同步更新读取路径。
- **A5 汇报组**：可引用华盛顿最终路网 41,679 个节点、99,543 条有向边；深圳转换复现统计为 85,287 个节点、176,241 条有向边，引用时注明版本与验证范围。

## 5. 集成注意事项

1. **路径与版本**：正式集成时保留单一数据权威位置，避免公共目录和 A1 工作区的 GraphML 长期出现不同版本；迁移时要同步修改调用路径与相关文档。
2. **原始数据范围**：`shenzhen.osm.pbf` 是裁剪产物，提供从深圳裁剪数据到 GraphML 的复现入口；广东上游原始 PBF 尚未纳入普通 Git，不应把两者混为一谈。
3. **共享代码范围**：A1-6 已修改 `src/path_planning/osm_loader.py`，因此原文“本次 A1 成果不包含核心共享代码修改”的说法不再适用；公共 API、前端代码并未因本次归档建议而自动迁移或修改。
4. **测试范围**：专项验收应明确区分全量属性核验与路径抽样对照；保留原始报告，不将未测试项目描述为 PASS。
5. **文件去重与提交管理**：不归档临时 GraphML、`.bak` 备份、乱码命名的误生成文件以及 `C:\a1_osm_test` 中的中间文件。转换器、GraphML、加载器和日志只维护一个正式版本。
6. **协作流程**：公共目录归档方案需由相关模块负责人确认；建议先保持 A1 工作区本轮提交完整，再通过独立 PR 进行主仓库公共目录迁移。

因此，建议当前仍以 `workspaces/A1_数据/` 为 A1 交付的原始归档位置，以本表作为后续公共目录整合的参考，不把“建议位置”误写成“已经迁移完成”。
