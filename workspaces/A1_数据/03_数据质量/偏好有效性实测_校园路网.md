# 偏好有效性实测：为什么 avoid_tolls 与 fastest 结果完全相同

> 记录日期：2026-09-29
> 记录人：初始由项目文档维护者实测填入，请 A1 数据线接手复核与补充
> 数据版本：`data/campus_552.graphml`（campus-552-v1，552 节点 / 1400 有向边）
> 复现脚本：`python tools/smoke_api.py`（接口层）、本文第 1 节的静态统计

## 一句话结论

**四种偏好里有两种在当前路网上"看起来没生效"**，但**原因不是代码错，是数据里缺少
可供惩罚的属性**。此外 `no_highway` 的实现有一处真实缺陷，需要修。

## 1. 静态数据统计

### 1.1 道路类型分布（按有向边数）

| road_type | 边数 |
|---|---|
| residential | 852 |
| unclassified | 317 |
| tertiary | 107 |
| secondary | 58 |
| **trunk** | **34** |
| primary | 12 |
| living_street | 8 |
| secondary_link | 7 |
| **trunk_link** | **5** |
| **motorway** | **0** |

### 1.2 与偏好实现相关的两个关键数字

| 项 | 数量 | 对偏好的影响 |
|---|---|---|
| `toll=True` 的边 | **0** | `avoid_tolls` 的 900 秒惩罚**永不触发** |
| `road_type ∈ {motorway, trunk}` 的边 | 34 | `no_highway` 的禁行规则**会触发**，但禁的是城市主干道 |

### 1.3 那 34 条 trunk 到底是什么

全部是 **珞喻路 / 珞喻东路**，即校园南侧的城市主干道，不是高速公路：

| 属性 | 实测值 |
|---|---|
| 道路名 | 珞喻路（29 条）、珞喻东路（5 条） |
| 限速 | **全部 30 km/h**（与 residential 同速） |
| 总长 | 8321.5 m |
| 另有无名 trunk_link | 5 条，257.1 m，也是 30 km/h |

> **这个限速值本身就是个信号**：`trunk` 在 OSM 里通常指限速 60–100 km/h 的干线，
> 而这里全部是 30 km/h。要么是数据来源把限速压平了（全图只有 30 与 60 两个取值），
> 要么是 `trunk` 标签在这片区域被用在了城市道路上。**两种解释都影响"最快路径"的可信度**，
> 需要 A1 回去核对 `graph.graphml` 的 `maxspeed` 原始标签。

## 2. 行为实测（40 组随机起终点，取最大强连通分量的 527 个节点内）

| 现象 | 实测结果 |
|---|---|
| 四种偏好给出 **2 种**不同代价 | 37 组 |
| 四种偏好给出 **3 种**不同代价 | 3 组 |
| `no_highway` 最终**不可达** | **4 组** |
| `no_highway` 与 fastest 路径不同 | 3 组 |
| `avoid_tolls` 与 fastest 代价不同 | **0 组** |

`shortest` 与 `fastest` 的差异是显著的，例如同一组起终点
`9346639920 → 1210354266`：

| 偏好 | cost |
|---|---|
| fastest | 296.60 |
| shortest | **2471.67** |
| avoid_tolls | 296.60（= fastest） |
| no_highway | 352.55（绕行，+18.9%） |

> `cost` 单位随偏好而变：`shortest` 用米，其余用秒。**两列的数值不能直接比大小**，
> 只能同类偏好之间比。这一点写进任何报告时都要标注，否则会被认为数字自相矛盾。

## 3. 两个需要处理的问题

### 问题 1（真实缺陷）：`no_highway` 漏了 `trunk_link`

`path_planning/costs.py` 的判定是：

```python
if self.preference is Preference.NO_HIGHWAY and edge.road_type in {"motorway", "trunk"}:
    return inf
```

而路网里存在 **5 条 `trunk_link`**（关山大道一带的匝道）。它们**不会被禁行**，
于是"避开高速"的结果是**半禁行**：主干道被掐断、匝道照走。

**证据**：40 组抽样中有 **4 组在 `no_highway` 下完全不可达**（fastest 却可达）。
一个"偏好"把路走没了，这在演示里是硬伤。

**建议**：把规则改成"前缀匹配"或显式枚举 link 类型：

```python
NO_HIGHWAY_TYPES = {"motorway", "motorway_link", "trunk", "trunk_link"}
```

同时决定：**不可达时应该报错还是自动回退？**
现在抛 `NoRouteError`（API 返回 404），前端需要能显示"该偏好下无可行路线"，
而不是转圈或空白。

### 问题 2（数据问题）：`avoid_tolls` 在当前数据上无法演示

0 条收费边 → 惩罚永不触发 → 结果与 fastest 逐位相同。

**三个可选处理，按推荐顺序**：

1. **换偏好语义**（推荐）：校园场景里"避开收费"没有意义。
   换成 **`prefer_main_road`（优先主干道）** 或 **`avoid_trunk`（避开珞喻路）**，
   后者正好能复用已有数据，且演示效果明显（珞喻路 30 km/h 与小路同速，
   绕行代价很小，路线差异会很好看）。
2. **换更真实的偏好**：A1 在作业 3 要接入交通事件与红绿灯，
   届时可换成 `avoid_congestion` / `prefer_less_turns`。
3. **保留但诚实标注**：如果课程要求必须保留四种偏好，
   就在报告里写明"当前路网无收费路段，该偏好退化为 fastest"。
   **这比假装它生效要好**——作业 3 的评分项里明确有"偏好能正确影响路径"。

> **注意**：这一条直接影响作业 3 的 **25% 分**（"偏好系统灵活、能正确影响路径"）。
> 现在不处理，到作业 3 会变成"四种偏好里一种永远没效果"。
