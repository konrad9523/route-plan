### 01_基准方法

**没有方法说明的数字不可信。** 必须写清：

| 项 | 要求 |
|---|---|
| 查询集 | 从哪个图、怎么采样、多少组、随机种子、文件在哪 |
| 预热 | 丢弃前几次（解释器预热、CPU 变频） |
| 重复次数 | **交错多轮、取中位数**（不要只跑一轮） |
| 计时范围 | 只计算法核心；排除数据加载、几何构建、可视化 |
| 环境记录 | CPU / 内存 / Python 版本 / 操作系统 |
| 公平性 | 同图、同查询集、同代价模型；**预处理时间单列** |

> **踩过的坑**：同一次测量按单轮跑，三次得到 +4.4% / +10.2% / +84%。
> 改成"交错多轮取中位数"后才稳定。**方法不对，数字全废。**

### 03_实验结果

放**实验本身**的结论，而不只是单个数字：

| 内容 | 说明 |
|---|---|
| CH 预处理 | 预处理时间、收缩顺序、捷径边数量、相对原始边数的比例 |
| 查询加速比 | 相对 A\* / Dijkstra |
| **解压正确性** | 见下方"CH 正确性怎么判"——**不要比边序列** |
| 消融实验 | 如 witness search 限 pop 次数、地标数量的影响 |
| **CH 与动态权重的边界** | 权重变化时捷径边失效——**必须显式回退并标注，不能给错误结果** |

> ### CH 正确性怎么判（**别比边序列**）
>
> 早先这里写"解压后的原始边序列是否与 Dijkstra 一致"——
> **这个要求会误判正确结果**：存在**等代价**路线时，CH 与 Dijkstra 可能给出
> **两条都最优但不同**的路径，比边序列会把它当成失败。
>
> 应判这三条：
>
> | 判据 | 说明 |
> |---|---|
> | **路径合法** | 解压出的边序列在原始图上**首尾相接、处处连通**，起终点正确 |
> | **代价一致** | 解压后的总代价与 Dijkstra 的最优代价**相等**（在容差内） |
> | **达到基准最优** | 该代价等于基准算法在同一图、同一权重下的最优代价 |
>
> 这与 §2.3 的对拍原则一致：**比较代价，不比较边序列**。
> 若需要更强的证据，再额外记录"等代价路径的条数"，而不是要求唯一。
>
> CH 依赖静态权重。交通权重变化时捷径边会**给出错误结果**，
> 因此"何时不能用 CH"本身就是一个必须写清的实验结论。
