# 武汉路网 A* 逐层改进与消融实验记录

> 归档整理：2026-10-12；历史实验日期为 2026-09-27。本次调整复现路径，不把历史耗时冒充新测结果。
> 代码在 `../01_基准方法/代码/`，结果见 `../02_基准结果/`、`../03_实验结果/`；先读[实验复现说明](../01_基准方法/武汉路网实验复现说明.md)。


## 摘要

针对武汉城市道路网络中单源单目的最短路径查询问题，本文以收件箱版本 A* 算法为基线，按照“图数据预处理与缓存—平面投影启发式—ALT 地标启发式”的顺序构建逐层改进方案，并通过消融实验分析各项改进对查询时间、搜索规模和路径正确性的影响。实验基于包含 91,638 个节点和 206,383 条有向边的武汉机动车路网，固定抽取 50 组有序起终点并进行 5 轮交错计时。结果表明：图数据缓存和局部平面投影主要降低单次查询的计算开销，对搜索节点数影响有限；ALT 地标启发式能够显著提高启发函数的紧致性，使平均展开节点数相对平面投影 A* 减少 69.6%。在本实验环境下，ALT-only 的热查询中位耗时为 26.681 ms/查询，优于平面投影与 ALT 的组合版本 31.955 ms/查询。所有单向算法均与独立 Dijkstra 参考结果一致，双向 A* 的最大绝对误差为 `5.82e-11 m`，小于设定容限。实验说明，对于固定路网和较大查询批次，ALT-only 是当前更具实际应用价值的方案。

## 1. 研究问题与改进层级

### 1.1 基线算法

收件箱版本 A* 采用如下评价函数：

```text
f(v) = g(v) + h(v)
```

其中，`g(v)` 表示起点到节点 `v` 的当前路径代价，`h(v)` 表示节点 `v` 到终点的启发式估计值。基线使用 Haversine 距离作为启发式函数，并已包含优先队列、堆中重复状态的惰性删除、启发值缓存、目标节点提前终止以及路径重建等机制。因此，上述内容不再作为工作版新增改进重复计数。

### 1.2 三项累计改进

本实验定义的累计改进严格包括以下三项：

1. 图数据预处理与缓存：降低重复查询中的图结构准备开销；
2. 平面投影启发式：降低几何启发函数的计算成本；
3. ALT 地标启发式：利用路网拓扑信息提高启发式下界的紧致性。

ALT-only 和 `max(平面投影, ALT)` 是第三项改进的两种实验变体，不构成两个独立改进。双向 A* 改变搜索结构，本文仅将其作为独立对照算法，不纳入上述三项累计改进。

## 2. 数据与实验方法

### 2.1 路网数据

实验输入为处理后的武汉机动车路网快照 `graph.pkl`。路网包含 91,638 个节点和 206,383 条有向边，最大强连通分量包含 90,284 个节点。边权采用道路长度，单位为米。数据校验结果显示，图中不存在负权边、非有限权重或未定义的邻接端点。

### 2.2 查询集构造

为避免不可达点对对实验结果的干扰，首先在有向路网上计算最大强连通分量；随后使用随机种子 2026，从该分量中抽取 50 组不重复的有序起终点，并排除起点与终点相同的情况。所有算法严格使用同一批查询。

### 2.3 计时与统计指标

实验采用 5 轮交错计时。每轮改变算法的执行顺序，使不同算法尽可能经历相近的系统负载。热查询耗时不包括路网文件读取、邻接表转换、强连通分量计算以及 ALT 地标预处理。工作版 `_Prepared` 的一次性构造时间和 ALT 的一次性预处理时间单独报告。冷启动控制组则在每次查询前清空 `_Prepared` 缓存，用于估计重复准备数据的成本。

评价指标包括：

- 每次查询的中位耗时以及 5 轮最小—最大范围；
- 平均展开节点数和平均入堆次数；
- 最后一轮查询中展开节点、入堆次数的最小值、中位数和最大值；
- 与独立 Dijkstra 结果的距离不一致数和最大绝对误差；
- 返回的节点路径、edge_id 序列及路径边长和的合法性。

## 3. 改进方法及理论分析

### 3.1 A* 启发式的正确性条件

设从节点 `v` 到终点 `t` 的真实最短路距离为 `d*(v,t)`。为了保证 A* 返回最优路径，启发式函数通常需要满足可采纳性：

```text
0 ≤ h(v,t) ≤ d*(v,t)
```

该条件要求启发式不能高估真实剩余代价。一致性是更强的局部条件：对于任意有向边 `u→v`，有：

```text
h(u,t) ≤ w(u,v) + h(v,t)
```

在道路长度作为代价的情况下，几何直线距离可以作为剩余道路距离的下界，但其紧致性通常较弱。ALT 通过预处理路网中的真实最短路距离提高下界质量。若未来将边权替换为行驶时间或其他综合代价，必须重新构造与该代价单位一致的启发式函数。

### 3.2 第一项改进：图数据预处理与缓存

#### 3.2.1 方法定义

在固定路网的多次查询场景中，图的拓扑结构和节点坐标在查询之间保持不变。若每次查询都重新整理邻接表、节点坐标和反向边，会产生与最短路搜索无关的重复开销。因此，工作版构造 `_Prepared` 数据对象，将查询过程中需要反复访问的结构预先整理并缓存，包括正向邻接关系、反向邻接关系、经纬度索引和节点规模等。

设路网包含 `|V|` 个节点和 `|E|` 条边，则一次性整理邻接结构的时间复杂度为 `O(|V|+|E|)`，空间复杂度同阶。缓存命中后，后续查询直接进入 A* 搜索循环，不再重复执行上述准备过程。

#### 3.2.2 作用边界

该改进不改变 A* 的评价函数、优先队列顺序或路径最优性，仅改变算法执行前的数据访问方式。因此，它不会直接减少展开节点，只能降低每个查询的固定准备成本和热循环中的数据访问成本。若路网边权、节点坐标或拓扑结构发生改变，缓存必须失效并重新构造；若仅执行一次查询，一次性准备成本也可能无法摊销。

在本实验中，工作版 Haversine A* 的平均展开节点与收件箱基线完全相同，但热查询耗时低于基线；冷启动控制组在每次查询前重新构造 `_Prepared` 后耗时显著上升，验证了缓存对重复查询的作用。

### 3.3 第二项改进：局部平面投影启发式

#### 3.3.1 方法定义

收件箱版本采用 Haversine 公式计算球面距离。对于覆盖范围相对有限的武汉路网，可将经纬度区域近似为局部平面。设节点坐标差转换为弧度后的纬度差和经度差分别为 `Δφ`、`Δλ`，两点平均纬度为 `φ_m`，则局部平面投影距离定义为：

```text
h_plane(v,t) = R × sqrt(Δφ² + (cos(φ_m) × Δλ)²)
```

其中 `R` 为地球平均半径。经度方向乘以 `cos(φ_m)` 用于修正经度弧长随纬度变化的影响。

#### 3.3.2 计算特性与适用条件

Haversine 需要多次三角函数运算，平面投影则使用一次余弦和一次平方根完成局部距离估计，因此单次计算成本较低。该改进的主要收益来自启发式计算速度，而非启发式质量提升。若平面投影与 Haversine 对节点产生相近的排序，A* 的展开节点数不会明显变化。

平面投影是否可以作为可采纳启发式，取决于坐标范围、边权定义和数值误差。本文边权为道路长度，且通过独立 Dijkstra 对拍验证了路径距离正确性；对于其他代价类型，不能直接复用该公式。工程上仍应检查边上的一致性条件 `h(u,t)≤w(u,v)+h(v,t)`，并对不同距离尺度的查询进行验证。

### 3.4 第三项改进：ALT 地标启发式

#### 3.4.1 预处理过程

ALT 通过少量地标节点将路网拓扑信息引入启发式函数。设选取 `k` 个地标集合 `L={L_1,...,L_k}`，本文采用 `k=8`。对每个地标 `L` 预处理两类距离：

```text
d(L,v)：地标 L 到节点 v 的最短距离
d(v,L)：节点 v 到地标 L 的最短距离
```

第一类距离通过在原图上从 `L` 运行 Dijkstra 获得，第二类距离通过在反向图上从 `L` 运行 Dijkstra 获得。若采用二叉堆实现，预处理时间约为 `O(k|E|log|V|)`，存储空间约为 `O(k|V|)`。预处理完成后，查询阶段不再运行地标最短路，而是读取距离表。

本文的地标选择采用基于地理坐标的分散策略：首先选择一个边界节点，随后迭代选择与已有地标集合距离最远的候选节点，以提高地标的空间覆盖范围。该策略并不保证对所有路网查询都最优，因此地标数量和选择方法仍属于后续实验变量。

#### 3.4.2 有向图下的启发式推导

对任意地标 `L`，由最短路距离满足的三角不等式：

```text
d(L,t) ≤ d(L,v) + d*(v,t)
```

可得：

```text
d(L,t) - d(L,v) ≤ d*(v,t)
```

另一方面：

```text
d(v,L) ≤ d*(v,t) + d(t,L)
```

因此：

```text
d(v,L) - d(t,L) ≤ d*(v,t)
```

在有向图中，ALT 启发式定义为：

```text
h_ALT(v,t) = max_L {
    d(L,t) - d(L,v),
    d(v,L) - d(t,L),
    0
}
```

其中每一项均为真实剩余距离的下界，因此对所有地标取最大值后仍具有可采纳性。对于无向图，常见形式可写为 `max_L |d(L,t)-d(L,v)|`；由于本文路网包含有向边，实验采用有向图形式，不能直接将其简化为无向图公式。

#### 3.4.3 搜索收益与代价

几何距离只提供空间上的下界，ALT 则利用地标距离间接反映道路绕行、单行限制和网络瓶颈。当 ALT 给出的下界显著大于几何距离时，A* 的 `f` 值排序会更接近真实代价，从而减少不可能位于最优路径上的节点扩展。

ALT 的代价包括地标预处理时间、距离表存储空间和查询阶段的 `O(k)` 启发式计算。增加地标数量通常会提高下界紧致性，但同时增加上述成本，并存在边际收益递减现象。因此，地标数量应通过实验确定，而不能仅凭理论预先指定最优值。

### 3.5 ALT 的实验变体与组合启发式

ALT-only 仅采用 `h_ALT`，用于测量第三项改进本身的收益。组合版本定义为：

```text
h_combined(v,t) = max(h_ALT(v,t), h_plane(v,t))
```

如果两个启发式均为可采纳下界，则取最大值仍然可采纳。不能未经证明直接使用 `h_ALT+h_plane`，因为两个估计可能重复计算同一段剩余距离，进而造成高估。

本实验将 ALT-only 和组合版本同时保留，是为了区分“地标带来的拓扑剪枝”和“平面投影带来的额外几何下界”。二者均属于第三项 ALT 改进的实验变体，而非两个独立改进。

## 6. 结果讨论

### 6.1 图缓存的作用

L1 与 L0 的平均展开节点完全一致，说明图数据缓存没有改变 A* 的搜索空间。L1 的耗时下降主要来自固定准备开销的消除和查询循环中的数据访问优化。该结果验证了第一项改进属于实现层优化，而非启发式或搜索策略优化。

### 6.2 平面投影的作用

L2 相对于 L1 的耗时降低 17.0%，但展开节点和入堆次数几乎不变，说明平面投影主要降低了 `h(v)` 的计算成本。平面投影单独使用仍具有工程价值，但其对路网拓扑的表达能力有限。

### 6.3 ALT 的作用

ALT-only 相对于 L2 将平均展开节点降低 69.6%，同时取得最低的热查询中位数。其主要贡献不是减少一次启发式函数的算术操作，而是利用地标距离构造更紧的剩余距离下界，从而改善优先队列中节点的排序质量。

### 6.4 组合启发式的边际收益

平面投影 + ALT 相对于 ALT-only 仅减少 5.9% 的展开节点，却使耗时增加 19.8%。这表明，在当前武汉路网和 8 个地标的设置下，ALT 已经覆盖了大部分可利用的方向信息，平面投影提供的额外下界不足以抵消其计算成本。因此，组合启发式适合作为“最少展开节点”实验版本，但不宜直接作为速度优先的默认实现。

### 6.5 双向 A* 的对照结果

双向 A* 相对于 L0 少展开 7.4%，但耗时增加 42.7%。双向搜索需要额外维护反向图、两套搜索状态、相遇点和安全停止条件，当前实验中这些额外成本超过了减少搜索节点带来的收益。因此，双向 A* 在本文中仅作为结构性对照，不纳入三项累计改进。

## 7. 结论

本文以收件箱 Haversine A* 为基线，对图数据缓存、平面投影和 ALT 地标启发式进行了逐层消融。实验结果支持以下结论：

（1）图数据预处理与缓存可以降低重复查询的固定开销，但不会减少 A* 展开节点；

（2）平面投影能够降低几何启发式的计算成本，但单独使用时对搜索规模的影响有限；

（3）ALT 地标启发式能够利用路网拓扑信息显著提高启发式下界的紧致性，是本实验中减少搜索节点最有效的改进；

（4）在本实验的武汉路网和 8 个地标设置下，ALT-only 的实际查询速度优于平面投影与 ALT 的组合版本；

（5）双向 A* 虽然保持路径正确，但当前额外维护成本较高，不宜作为默认方案。

综合考虑热查询性能、预处理成本和正确性，固定路网的大批量查询可优先采用 ALT-only；查询批量较小或路网变化频繁时，平面投影 A* 更具成本优势。地标数量消融实验进一步表明：4 个地标的 50 次查询摊销成本最低，8 个地标在搜索规模和热查询性能之间较为均衡，16 个地标虽然继续减少展开节点，但查询耗时和预处理成本均明显增加。后续优化重点应放在地标选择策略，而不是简单增加地标数量。
