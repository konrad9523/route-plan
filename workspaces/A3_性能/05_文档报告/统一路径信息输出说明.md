# 统一路径信息输出说明

更新：2026-10-18。范围：A3 距离最短路的路径结果整理与边行驶时间估算；不改 A2 基线、搜索代价、C++ ABI 或历史性能结果。

## 1. 修改方式

保留原搜索返回值 `(node_path, edge_path, distance_m, expanded_nodes)`，新增 `01_基准方法/代码/route_output.py` 中的 `build_route_output()`。搜索完成后调用它，校验路径并汇总信息；整理和 JSON 序列化放在搜索计时之外。

这样 Dijkstra、A*、各优化层和 C++ 返回的路径共用一个输出规则，不需要逐个修改算法。C++ 先把已有结果转换成相同四元组即可，无需重新编译 DLL。

临时目录 `A3_临时工作区/06_CHATGPT/基础代码与优化测试结果/` 保存相同的模块、演示及测试文件，两份 Notebook 均在末尾增加独立的结果展示单元。旧 `性能优化与API/` 不作为这次接入入口；其中旧 A* 的最优性问题、以及新版双向 ALT 的重标权问题不在本次输出改动范围内。

## 3. 输入约定与接入

```python
from time import perf_counter
from route_output import build_route_output

started = perf_counter()
raw_result = run_algorithm("L4", source, target)  # 原有搜索调用
planning_ms = (perf_counter() - started) * 1000
route = build_route_output(
    raw_result, edge_records, source, target,
    algorithm="dijkstra-L4", planning_ms=planning_ms,
)
```

- 四元组的代价必须是以米计的距离，不能把时间权重或带偏好惩罚的代价当作米传入。
- `edge_records` 可直接使用武汉 `graph_data["edges"]` 的六元组边表：`(u, v, length_m, road_type, name, speed_kmh)`；缺失速度使用 `None`。
- `RoutePlanner.from_pickle()` 会优先读取同目录的 `wuhan_distance_v2.graphml`，从 `source_tags.maxspeed` 恢复 OSM 限速；也可通过 `source_graphml=` 显式指定。它按 GraphML 行顺序对应 `edge_id`，并逐条校验方向端点和边数；不一致时加载失败，避免限速错配，且允许存在平行边。
- 也可传入以边编号为键的字典，值至少包含 `from_node`、`to_node`、`length_m`，可选 `speed_kmh`、`speed_source`、`travel_time_s`、`road_type`、`name`。没有 OSM 限速时，支持的道路等级会使用下表中的估算速度；未映射等级仍标记为缺失。
- 前端仍只需在启动时创建并复用一个 `RoutePlanner`，查询时调用 `plan()`；Notebook 和 GraphML 速度解析都不属于每次查询逻辑。
- 对深圳脚本/C++ 已有的结果字典 `r`，四元组写成 `(r["nodes"], r["edge_ids"], r["distance_m"], r["expanded_nodes"])`。边属性字典要使用真实 edge_id，不能用端点二元组代替边编号。
- 路径的方向、边数量、边编号和长度总和必须一致，否则报错，不输出貌似正常的结果。

## 4. 时间如何计算

每段速度按以下优先级确定：明确提供的 `travel_time_s` → OSM `maxspeed` → 边记录中的 `speed_kmh` → 道路等级估算速度 → 显式传入的 `assumed_speed_kmh`。OSM 数值限速按 km/h 解释，并在本实验中将其作为该路段的平均行驶速度使用。距离和速度换算为：`duration_s = length_m / (speed_kmh / 3.6)`。

道路等级回退值沿用既有数据管线中的 `DEFAULT_SPEED`；这些值是模型估算，不是 OSM 限速或实测平均车速：

| OSM `highway` 道路等级 | 估算速度 (km/h) | OSM `highway` 道路等级 | 估算速度 (km/h) |
|---|---:|---|---:|
| `motorway` | 100 | `motorway_link` | 60 |
| `trunk` | 80 | `trunk_link` | 50 |
| `primary` | 60 | `primary_link` | 40 |
| `secondary` | 50 | `secondary_link` | 35 |
| `tertiary` | 40 | `tertiary_link` | 30 |
| `unclassified` | 30 | `residential` | 30 |
| `living_street` | 15 | `service` | 20 |

武汉当前图与同目录 GraphML 配对后，2,001 条有向边具有可解析的数值 `maxspeed`，其余 205,164 条边按道路等级估算；当前 14 种道路等级均有对应值。若其他路网出现未映射的道路等级，该路段仍无法计算时间，总 `duration_s` 为 `null`、`duration_status` 为 `missing`，不会用部分之和冒充总时间。起终点相同时，总距离和时间均为 0。

本次只规划距离最短路线；`duration_s` 是该路线上的估算行驶时间，不参与 Dijkstra/A* 的边权，也不表示时间最短路线。`duration_scope="edge_travel_only"`：不包括转向、红绿灯、拥堵或停车等待。`duration_status="complete"` 仅表示每段都有速度依据，不代表真实交通或实时 ETA。输出逐段 `speed_source` / `duration_source`：`osm_maxspeed`、`edge_speed_kmh`、`road_class_estimate`、`assumed_speed_kmh`、`provided_travel_time_s` 等；道路等级估算段数会同时写入 `warnings`。

## 5. 输出字段

| 字段 | 含义 |
|---|---|
| `schema_version` | 本实验约定 `a3.route.v1`，不是全组已批准的接口 |
| `status` | `ok` / `no_route` |
| `algorithm`、`source`、`target` | 算法标识和本图节点编号 |
| `node_ids`、`edge_ids` | 有序节点、实际有向边序列 |
| `distance_m` | 路段长度总和，米 |
| `duration_s` | 路段通行时间总和，秒；缺失时 `null` |
| `duration_status` | `complete` / `missing` / `not_applicable`（不可达） |
| `duration_scope` | `edge_travel_only` |
| `duration_semantics` | 说明这是距离最短路线的估算时间、限速使用假设及未包含的因素 |
| `cost`、`cost_unit` | 原搜索代价，本次仅支持米 |
| `expanded_nodes`、`planning_ms` | 搜索展开数、算法运行毫秒数；不等于行程时间 |
| `segments` | 逐段信息，顺序与 `edge_ids` 一致 |
| `warnings` | 缺失时间、使用假设速度等说明 |

每个 `segments` 元素包含 `sequence`（从 1 开始）、`edge_id`、`from_node`、`to_node`、`length_m`、`speed_kmh`、`speed_source`、`duration_s`、`duration_source`、`road_type`、`name`。`speed_source="road_class_estimate"` 明确表示该段采用道路等级估算值。

不可达时序列为空，距离、时间、代价为 `null`，不把非标准 JSON 的 `Infinity` 导出。序列化使用 `json.dumps(route, ensure_ascii=False, allow_nan=False)`。
