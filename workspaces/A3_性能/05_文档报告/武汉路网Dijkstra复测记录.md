# 武汉路网 Dijkstra 复测记录

> 归档整理：2026-10-12；历史实验日期为 2026-09-27。本次调整复现路径，不把历史耗时冒充新测结果。
> 代码在 `../01_基准方法/代码/`，结果见 `../02_基准结果/`、`../03_实验结果/`；先读[实验复现说明](../01_基准方法/武汉路网实验复现说明.md)。


日期：2026-09-27

目的：在武汉城市道路图上，对比收件箱原版 Dijkstra 与 GPT 工作版普通 Dijkstra；检查此前工作版的平面势函数重加权分支是否满足其使用前提。

算法源码未修改；本次新增的测试脚本和结果均保存在 `06_CHATGPT`。

## 1. 数据

- 输入：`cache/a3_wuhan/processed/graph.pkl`。
- 原始来源：`wuhan_drive.osm`，Overpass API 下载的武汉机动车道路数据；本次直接读取处理好的快照，没有重新下载、复制或改写数据。
- 规模：91,638 个节点、206,383 条有向边；最大强连通分量 90,284 个节点。
- 代价：道路长度，单位米；本图没有负权或非有限权重（0 条）。
- 输入快照采用标准库 `array` 数组；脚本把 CSR 转换成收件箱算法需要的二元组邻接表，以及工作版需要的带 `edge_id` 三元组邻接表。转换时间不计入查询耗时。

数据规模依据 `../01_基准方法/武汉路网_meta.json` 和实际载入结果。原始下载信息在 `../01_基准方法/武汉路网_download_meta.json`。

## 2. 方法

1. 通过迭代 Kosaraju 算法求最大强连通分量，避免随机点对不可达导致把“搜完整个可达区域”的耗时混入一般路线查询。
2. 使用 `random.Random(2026)` 从该分量抽取 50 组互不重复的有序起终点，排除起点等于终点。所有版本使用同一批查询。
3. 逐组用收件箱 `dijkstra.py` 作参考，与工作版普通 Dijkstra 对比距离，并核验工作版返回的每个 `edge_id` 是否对应路径中的有向边、边长之和是否等于返回距离。
4. 对同一批 50 组查询做 5 轮交错计时，每轮改变算法运行顺序；计时仅包括预热后的查询，不包括读文件、CSR 转换、求 SCC 和工作版一次性 `_Prepared` 构造。报告中同时单列 `_Prepared` 构造时间。
5. 工作版 `use_reduced=True` 的平面投影分支要求每条重加权边 `w+h(v)-h(u)` 非负。对 50 个目标逐一检查全图所有边；发现违例后，不运行该分支的正确性或性能测试，也不把它的表现报告成有效结果。

可复现入口：`../01_基准方法/代码/wuhan_dijkstra_benchmark.py`。机器可读输出：`../01_基准方法/代码/wuhan_dijkstra_results.json`。

## 3. 结果

### 正确性

| 检查 | 结果 |
|---|---:|
| 工作版普通 Dijkstra 与收件箱版距离不一致 | 0/50 |
| 最大绝对距离差 | 0 m |
| 工作版 `edge_id` 路径方向/边权核验失败 | 0/50 |
| 两版平均扩展节点数 | 均为 44,819.42 |

### 查询耗时

| 版本 | 5 轮中位数（ms/查询） | 各轮范围（ms/查询） | 平均扩展节点 |
|---|---:|---:|---:|
| 收件箱原版 Dijkstra | 74.587 | 72.725–79.887 | 44,819.42 |
| GPT 工作版普通 Dijkstra（h=0） | 73.898 | 70.196–81.126 | 44,819.42 |

两版扩展数完全相同；工作版中位数约低 0.9%，但各轮范围明显重叠，因此本次结果**不能证明工作版普通 Dijkstra 有稳定的搜索或速度优势**。在热查询之外，工作版 `_Prepared` 首次构造单独耗时 149.175 ms；本表没有把这项一次性准备开销计入工作版查询时间。若只运行一次、且之前未共享准备数据，工作版的端到端耗时会额外承担该成本。

### 平面势函数可行性

| 检查 | 结果 |
|---|---:|
| 目标数 | 50 |
| 目标 × 全图有向边检查数 | 10,319,150 |
| 重加权边小于 `-1e-5 m` 的次数 | 1,627 |
| 最小重加权边 | -0.029460 m |

因此这张武汉图上，当前工作版的**平面投影重加权 Dijkstra 分支没有通过可行性前提检查**，本轮将其标记为未测，不给出它的最短路正确性或速度结论。这不影响工作版普通 Dijkstra（h=0）与收件箱原版的对拍结果。

## 4. 执行过程与限制

- PATH 中的 `python` 启动失败（uv trampoline 报 permission denied），之后使用 Codex 提供的 Python 运行时执行。
- 第一次运行测试脚本时，脚本回溯项目根目录多退了一层，因而找不到收件箱 `dijkstra.py`；当时在导入阶段停止，未开始算法测试、未写结果文件。修正路径后成功运行。
- 本次为了检查平面势函数，新增了按目标逐边检查的实验；该检查结果是对所测 50 个目标的边一致性检查，不是对所有可能目标的数学证明。
- 只测试本次明确的 Dijkstra 版本；没有重跑 A*、双向 A*、可视化或项目全套测试，也没有修改 DSH 目录和 `02_A3工作区` 数据。
- 本轮查询数（50）小于校园网之前使用的 500 组；武汉图规模大得多，当前结论仅适用于这批固定点对和本机运行环境。后续如要提高统计把握，可在确认耗时预算后扩大查询集。

## 5. 结论

武汉城市路网放大到 91,638 个节点后，收件箱原版与工作版普通 Dijkstra 仍给出完全一致的距离和相同的搜索扩展数。工作版在本次暖机计时中只出现不到 1% 的中位耗时差，且计时范围重叠；主要增量仍是边级路径输出、统计接口及可复用预处理，而不是普通 Dijkstra 搜索策略变优。工作版的平面重加权分支在这张路网发现负重加权边，不能未经修正就宣称满足 Dijkstra 的非负边权前提。
