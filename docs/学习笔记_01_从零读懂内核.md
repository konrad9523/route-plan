## ③ 本项目的依赖：好消息是几乎不需要

这是你们项目的一个**巨大优势**，必须知道：


```powershell

```

建完记得在 PyCharm 里把解释器切到 `.venv`（否则 PyCharm 跑的和终端跑的可能不是同一个 Python）。

> 注意：`.venv/` 已经写进 `.gitignore` 了，不会误提交到版本库。

## ⑨ 重要提醒：PyCharm 可能有"两个 Python"

这是新手最迷惑的问题之一：

- **终端里的 Python**：就是敲 `python --version` 出来的那个；
- **PyCharm 运行/测试按钮用的 Python**：是项目解释器设置里指定的那个。

# 第 1 课：一张地图在电脑里长什么样

## ① 要回答的问题

电脑不认识"路"，它只认识数字和列表。那一条马路，在程序里到底是什么？

## ② 先跑起来

```powershell
python -m unittest discover -s tests -v
```

你应该看到 7 行 `... ok`，最后一行是 `OK`。

**这一步不用理解测试在测什么**，只要确认一件事：**我能让它跑起来。** 这是所有后续工作的地基。

## ③ 打开 `path_planning/models.py`，只看 4 个东西

这个文件 151 行，但你现在只需要认 4 个"名词"：

| 名词 | 在哪几行 | 大白话 | 举个例 |
|---|---|---|---|
| `Node` | 16–27 | 一个**路口**（一个点） | 编号 1，坐标 (114.30, 30.50) |
| `Edge` | 30–42 | 一段**马路**（一条线） | 编号 101，从 1 号路口到 2 号路口，长 1000 米，限速 30 |
| `Graph` | 108–151 | 装所有点和线的**盒子** | 整张地图 |
| `RouteResult` | 69–105 | 算完之后交给别人的**结果单** | 走路、总距离、总时间 |

再看两个"动作"（这是全项目最常用的两个方法）：

```python
# models.py 第 120 行
graph.add_node(Node(1, 114.3, 30.5))        # 往地图里加一个路口

# models.py 第 126 行
graph.add_edge(Edge(101, 1, 2, 1000, 30))   # 往地图里加一段路
```

`Edge(101, 1, 2, 1000, 30)` 这 5 个数字按顺序是：

```text
101      1        2        1000        30
 ↓        ↓        ↓         ↓          ↓
编号   从哪来    到哪去    长度(米)   限速(km/h)
```

## ④ 核心：为什么叫"有向图"

请特别注意 `1, 2` 这个顺序，它是**有方向**的：`Edge(101, 1, 2, ...)` 的意思是"**只能从 1 开到 2**"，不能反过来开。

这就是为什么项目叫"**有向**图"。它的意义在于：

```text
单行道（只能东→西）：只 add_edge 一次
双行道（两边都能开）：add_edge 两次
                      Edge(101, 1, 2, ...)   ← 1 到 2
                      Edge(102, 2, 1, ...)   ← 2 到 1
```

**如果你偷懒把双行道只写一条边**，程序就会给你规划出**逆行**路线——这是导航系统最不能犯的错误，也是答辩必被问的点。

## ⑤ 停下来自问

> **问**：一条双向行驶的马路，我该调用几次 `add_edge`？
> **答**：2 次，两个方向各一条。

> **问**：`Graph` 里第 117 行的 `_out_edges` 是干什么的？
> **答**：提前记好"每个路口能通向哪些路"，这样搜索时不用遍历全部边去找，直接查表。这叫**邻接表**。（现在记不住没关系，第 4 课还会用到）

## ⑥ 小实验

打开 `path_planning/demo.py`，看第 14–27 行，这是那张 4 个点的假地图：

```text
1号点 (114.30, 30.50)  ————101————→  2号点 (114.31, 30.50)    ← 下面这条横路
                                                              ↓
3号点 (114.30, 30.51)  ————104————→  4号点 (114.31, 30.51)    ← 上面这条横路
       ↑                                              ↑
     103（左边竖路）                                 102（右边竖路）
```

**画出来是这样**：

```text
   3 ●────────104───────● 4
     │                   │
    103                 102
     │                   │
   1 ●────────101───────● 2
```

注意：`102` 是 `2 → 4`（向上），`103` 是 `1 → 3`（向上）。所以从 1 走到 4 有两条路：

- **下面绕**：`101 + 102` = 2000 米
- **上面绕**：`103 + 104` = 2600 米

**动手**：在纸上把这 4 个点和 4 条边画出来，标上方向和长度。这一步别省，画完你对"图"就有画面感了。

# 第 2 课：跑起来，看懂程序的输出

## ① 要回答的问题

程序跑完之后打印的那堆东西，每个数字是什么意思？

## ② 先跑起来

```powershell
python -m path_planning.demo
```

你会看到三行很长的 JSON。为了好读，我们整理成表格。**下面左边是程序真实输出，右边是解读**：

| 偏好 | 走的路 | 总距离 | 预计时间 | 代价 cost |
|---|---|---|---|---|
| `fastest` | `[103, 104]` 走上面 | 2600 m | 117.0 s | 117.0 |
| `shortest` | `[101, 102]` 走下面 | 2000 m | 245.0 s | 2000.0 |
| `no_highway` | `[101, 102]` 走下面 | 2000 m | 245.0 s | 245.0 |

先看懂这张表，比读一百行代码有用。

**逐列解释**：

- **走的路**：`edge_ids`，就是一串马路编号。`[103, 104]` 意思是"先走 103 号路，再走 104 号路"。
- **总距离**：`distance_m`，走过的马路长度加起来。
- **预计时间**：`duration_s`，按每条路的限速算出来的行驶时间，**再加上转弯等待**。
- **代价**：`cost`，**这是算法真正在最小化的那个数**。

## ④ 核心：三个关键认知

### 认知一：为什么 `fastest` 明明更远（2600 > 2000），却被选为"最快"？

因为**距离短 ≠ 时间短**。看 `demo.py` 第 25 行：

```python
Edge(103, 1, 3, 1300, 80, road_type="motorway", toll=True, ...)
                                ↑
                          限速 80 km/h（高速）
```

上面那条路是**高速**，限速 80；下面那条是普通路，限速 30。所以：

```text
走下面：2000 米 ÷ 30 km/h ≈ 245 秒
走上面：2600 米 ÷ 80 km/h ≈ 117 秒   ← 虽然远，但快一倍
```

**这就是导航为什么要分"最短"和"最快"**——绕一点但走快速路，通常更省时间。

### 认知二：`cost` 这一列的数字，单位不一样！

这是全项目**最容易踩的坑**，请务必记住：

| 偏好 | `cost` 的单位 | 为什么 |
|---|---|---|
| `shortest` | **米** | 它在最小化"距离" |
| `fastest` | **秒** | 它在最小化"时间" |
| `no_highway` | **秒** | 它也在最小化时间，只是禁掉了高速 |
| `avoid_tolls` | **秒** | 同上，只是给收费路段加了罚时 |

所以 **`shortest` 的 2000 和 `fastest` 的 117 不能直接比较大小**——一个是米，一个是秒。

> 项目文档 `路径规划模块开发说明.md` 第 70 行专门写了这一条，说明前人已经踩过这个坑。

**但 `duration_s`（预计时间）永远是秒，可以跨偏好比较。** 这一点非常有用：想横向比较不同路线谁更快，看 `duration_s`，别看 `cost`。

### 认知三：245 秒是怎么来的？

下面那条路 `101 + 102` 各 1000 米、限速 30：

```text
1000 米 ÷ (30 × 1000 ÷ 3600) 米/秒 = 1000 ÷ 8.333 = 120 秒
两条路：120 + 120 = 240 秒
再加转弯：demo.py 第 30 行的 TurnRule(101, 102, penalty_s=5) → 在 2 号路口拐弯等 5 秒
合计：245 秒  ✓ 和程序输出一致
```

这就是 `duration_s` 的完整算法。**看懂这个，你就看懂了 `router.py` 第 46–61 行在干什么。**

# 第 3 课：`costs.py` —— 项目的灵魂

## ① 要回答的问题

"最短路线"和"最快路线"的差别，到底写在哪几行代码里？

## ② 打开 `path_planning/costs.py`（只有 64 行）

这个文件是**整个项目的灵魂**。它只有 64 行，但决定了所有路线的样子。

## ③ 看第 33–43 行 `edge_cost()`

```python
def edge_cost(self, edge: Edge) -> float:
    if edge.closed or self.mode not in edge.allowed_modes:
        return inf                        # ① 封路 / 车型不允许 → 此路不通
    if self.preference is Preference.NO_HIGHWAY and edge.road_type in {"motorway", "trunk"}:
        return inf                        # ② 选了"避开高速" → 高速不通
    if self.preference is Preference.SHORTEST:
        return edge.length_m              # ③ 最短模式：代价 = 这条路的米数
    travel_time_s = edge.length_m / (edge.speed_kmh * 1000 / 3600)
    if self.preference is Preference.AVOID_TOLLS and edge.toll:
        travel_time_s += self.toll_penalty_s
    return travel_time_s                  # ④ 最快模式：代价 = 这条路的秒数
```

**逐块读懂**：

- **① `return inf`**：`inf` 是"无穷大"。返回无穷大 = **告诉算法这条路走不得**。这是表达"硬性禁止"的方式（封路、车型不符）。
- **②**："避开高速"的实现就是——遇到 `motorway`/`trunk` 直接返回无穷大。
- **③**：`SHORTEST` 模式返回**米数**。这就是为什么第 2 课里 `shortest` 的 `cost` 单位是米。
- **④**：`edge.length_m / (edge.speed_kmh * 1000 / 3600)` 就是**距离 ÷ 速度 = 时间**。其中 `× 1000 ÷ 3600` 是把 km/h 换算成 m/s。这个除法你在第 2 课的实验里已经手工算过了。

## ④ 核心：算法根本不认识"最短"和"最快"

这是最反直觉、但最重要的一句话：

> **算法完全不知道自己在算距离还是时间。它只会一件事：找"总代价最小"的那条路。**

"最短"和"最快"的全部区别，**仅仅在于 `edge_cost()` 返回米还是秒**。

所以以后你想加新偏好（"避开收费""少红绿灯""风景路线"），做法永远是一样的：**改这个函数，让它返回不同的数字**。算法一行都不用动。

这就是为什么 `报告.md` 里说要"把权重逻辑封装成 CostModel，不要把业务判断写进搜索主循环"——**换权重不动算法，这是好架构**。

## ⑤ 再看第 44–57 行 `transition_cost()`

这个函数处理"转弯"：

```python
def transition_cost(self, graph, previous: Edge | None, current: Edge) -> float:
    if previous is None:
        return 0.0                                    # 刚开始走，没有上一条路
    rule = graph.turn_rules.get((previous.edge_id, current.edge_id))
    if rule is None:
        return 0.0                                    # 这个路口没有转弯规则
    if rule.forbidden:
        return inf                                    # 禁止转弯 → 此路不通
    if self.preference is Preference.SHORTEST:
        return 0.0                                    # 最短模式：转弯不加米数
    return rule.penalty_s                             # 转弯等待 N 秒
```

**它的输入是"上一条路 + 这一条路"这一对**，而不是单个路口。为什么？

因为"能不能左转"取决于**你从哪条路拐进来**。同一个路口，从东路进来可能禁止左转，从南路进来就能左转。这是真实导航必须处理的，也是 `router.py` 第 20–22 行那个 `_State(previous_edge_id, node_id)` 设计的原因。**这个设计是你们项目的一个亮点，答辩时可以讲。**

# 第 4 课：`router.py` 的搜索主循环（最难，也最关键）

## ① 要回答的问题

算法怎么"找路"？它凭什么保证找到的是最短的那条？

## ② 先把概念讲清楚：待办清单

先忘掉代码，讲个生活例子。

你要从家走到一个没去过的商场，怎么找最短的路？

朴素办法是：**从家开始，每一步都选择"当前已经确定最便宜"的地方继续往外探**。具体做法：

1. 拿一张**待办清单**，先写上"从家出发，已花 0 米"。
2. 从清单里挑出**已花代价最小**的那一项，拿出来处理。
3. 看看从那儿能去哪，把新地点连同"总花费"写进清单。
4. 重复 2–3，直到清单里出现目的地。

**为什么这样一定是最短？** 因为每次拿出来的都是"当前最便宜"的。如果有一条更便宜的路能到某地，它一定会在更早的时候被拿出来。这是 Dijkstra 在 1959 年给出的证明，你现在只需要**记住这个直觉**。

## ③ 打开 `router.py`，看第 99–126 行

```python
while queue:                                    # 只要待办清单非空
    _, current_cost, state = heappop(queue)     # 取出"当前最便宜"的那项
    if current_cost != best.get(state):
        continue                                # 过期的旧记录，跳过
    expanded_states += 1
    if state.node_id == target:                 # 到终点了吗？
        final_state = state
        break                                   # 到了，收工
    previous_edge = graph.edges.get(state.previous_edge_id)
    for edge in graph.out_edges(state.node_id): # 看看从这里能去哪
        edge_cost = model.edge_cost(edge)       # 这段路多贵？（第 3 课看的函数）
        if edge_cost == inf:
            continue                            # 此路不通，跳过
        turn_cost = model.transition_cost(graph, previous_edge, edge)  # 转弯费
        if turn_cost == inf:
            continue
        next_state = _State(edge.edge_id, edge.to_node)
        new_cost = current_cost + edge_cost + turn_cost
        if new_cost >= best.get(next_state, inf):
            continue                            # 不是更便宜的路，不用记
        best[next_state] = new_cost             # 记下"到这儿的最优花费"
        parent[next_state] = (state, edge.edge_id)   # 记下"我是从哪来的"
        priority = new_cost
        if algorithm == "astar":
            priority += model.heuristic(graph, graph.node(edge.to_node), target_node)
        heappush(queue, (priority, new_cost, next_state))   # 放进待办清单
        queue_pushes += 1
```

**就是上面那个生活例子的逐行翻译。** 一一对应：

| 生活例子 | 代码 |
|---|---|
| 待办清单 | `queue` |
| 挑出"当前最便宜"的 | `heappop(queue)` |
| 已花代价 | `current_cost` |
| 此路不通 | `return inf` → `continue` |
| 到目的地了 | `if state.node_id == target` |
| 记下"到这儿的最优花费" | `best[next_state] = new_cost` |
| 记下"我是从哪来的" | `parent[next_state] = (state, edge.edge_id)` |

**这 28 行就是 Dijkstra 的全部。** 你现在已经读完了本项目最难的代码。

## ④ 核心一：`heappop` 是什么？为什么要用它？

`heappop(queue)` 的作用是"**从清单里取出最小的那一项**"。

如果你用普通列表，每次都得从头扫一遍找最小值，太慢。`heapq` 是一个专门为此优化的数据结构（叫"堆"），取最小值只要一瞬间。**这就是"用优先队列优化 Dijkstra"的含义**，也是作业要求里的第 1 条。

## ⑤ 核心二：`parent` 是干什么的？

搜索过程中，程序只记得"到每个地点的最优花费"，并不知道完整路线。`parent` 记录的是**每个地点的前一步是谁**。

就像你出门时在每个路口都留个路标："我是从那边来的"。到了终点后，顺着路标一路倒着走回家，路线就出来了——这就是 `router.py` 第 25–62 行的 `_reconstruct()`（"路径重建"）。

## ⑥ 核心三：A* 只差一行

回看第 122–124 行：

```python
priority = new_cost
if algorithm == "astar":
    priority += model.heuristic(graph, graph.node(edge.to_node), target_node)
heappush(queue, (priority, new_cost, next_state))
```

**Dijkstra 和 A* 的区别只有这一处**：

- **Dijkstra**：放进清单时用 `new_cost`（已经花了多少）当排序依据。
- **A\***：用 `new_cost + 到终点的估算距离` 当排序依据。

效果就是：A* 会把"离终点更近"的地点**优先**拿出来处理，于是不会像 Dijkstra 那样四面八方均匀地乱摸，而是**朝终点方向摸**。这就是 A* 更快的原因。

我在你们真实的 552 点校园地图上实测过：

| 偏好 | Dijkstra 需要摸的点数 | A* 需要摸的点数 |
|---|---|---|
| fastest | 365 | 288 |
| shortest | 400 | **133** |

"最短"模式下 A* 只摸了三分之一的点——**这就是 A* 的价值，也是你们报告里最该有的一张表。**

## ⑦ 停下来自问

> **问**：`best` 这个字典存的是什么？
> **答**：到每个"状态"的最低已知花费。它是"我们目前掌握的最优信息"。

> **问**：为什么 `_State` 里要存 `previous_edge_id`？
> **答**：因为转角规则需要知道"从哪条路来"。同一个路口，从不同路进来，允许的下一步不同。

> **问**：A* 比 Dijkstra 少了什么？多了什么？
> **答**：少了"均匀乱摸"；多了"+ 到终点的估算"这个排序加分项。
