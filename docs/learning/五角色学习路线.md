我在核实项目时发现的，**对你们价值很大**：

```bash

```


它提供：[OSRM Python API 文档](https://raw.githubusercontent.com/Project-OSRM/osrm-backend/master/docs/python/api.md)

# 1. A1 数据线（P4）学习路线

**职责**：路网怎么进来、怎么存、怎么压。跨四次作业从 552 节点做到 100 万节点。

### 1.1 你应该已经会的

`docs/learning/notes/学习笔记_02_把真实路网接进来.md` —— 读 GraphML、WKT 解析、三个数据坑。

### 1.2 路线

### 阶段 1：从小图到大图（当前最紧急）

**任务**：把 552 节点换成 10 万+ 节点。

| 学什么 | 资源 | 要跑出什么 |
|---|---|---|
| 按区域下载 OSM 数据 | [Geofabrik 下载站](https://download.geofabrik.de/) | 下载到武汉或湖北省 `.osm.pbf` |
| 裁剪出合适大小的区域 | [osmium-tool](https://github.com/osmcode/osmium-tool) | 用 `osmium extract` 裁出目标区域 |
| **用 Python 读 OSM 原始数据** | [pyosmium](https://github.com/osmcode/pyosmium)（[文档](https://docs.osmcode.org/pyosmium/latest/user_manual/01-First-Steps/)） | 写出一个脚本统计某区域的节点/路边数 |
| 从小区域构建路网 | [OSMnx](https://github.com/gboeing/osmnx) | 用 `graph_from_bbox` 抓城市级路网并存 GraphML |

**为什么先学 osmium 而不是 OSMnx**：OSMnx 方便但**隐藏了数据细节**。你要做的是"数据工程"，
必须理解 PBF 里 Node/Way/Relation 怎么变成边。**先看懂原始数据，再用封装工具。**

> **最快的路径**：先用 OSMnx 抓到城市级 GraphML（你们现有的 `osm_loader.py` 直接能读），
> **这一步就能让作业 2 的"10 万节点"达标**。然后再慢慢学 osmium 做更精细的控制。

### 阶段 2：图结构压缩（作业 2 的核心）

**任务**：现在 `dict[int, Node]` + 不可变 dataclass 在 10 万节点上要几百 MB，换成 CSR。

| 学什么 | 资源 | 要跑出什么 |
|---|---|---|
| CSR 结构（数组化邻接表） | [scipy.sparse.csr_matrix 文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.sparse.csr_matrix.html) | 理解 `indptr` / `indices` / `data` 三个数组 |
| 真实工程里怎么做 | [RoutingKit 的 `Side` 结构](../../第三方代码/references/RoutingKit/include/routingkit/contraction_hierarchy.h) | 看它如何用 `first_out` + `head` + `weight` 表示图 |
| 节点 ID 重映射 | 自己实现 | OSM 的 ID 是 `9626752368` 这种大数，映射成 `0..N-1` |

**验收标准**：同一张 10 万节点的图，CSR 版本的内存占用比现有 `dict` 版本**低一个数量级**，
且查询结果与 `dict` 版本**完全一致**（用对拍）。

### 阶段 3：几何数据外置（作业 4 的伏笔）

**任务**：`Edge.geometry` 现在是饿汉式加载，10 万节点时它会是最大内存项——但**搜索根本不用它**。

**做法**：几何单独存一个文件（二进制/NumPy），按需读取。

### 1.3 你不必学的

- ❌ PostGIS / PostgreSQL（课程项目用不上，别被文档里的工具表带偏）
- ❌ GDAL 的复杂用法（除非要做 DEM）
- ❌ C++ 编译 OSRM（除非要用它当基准）

# 2. A2 算法正确线（P1）学习路线

**职责**：路线算得**对不对、优不优**。跨四次作业从 Dijkstra 做到能耗模型。

### 2.1 你应该已经会的

`docs/learning/notes/学习笔记_01_从零读懂内核.md`（读懂内核）+ `docs/learning/notes/学习笔记_03_修掉两个缺陷.md`（修两个缺陷）。

### 2.2 路线

### 阶段 1：把启发式做对（作业 1 的 20% 分）

这是**当前最该做的事**——原文要求"欧氏距离/地标距离"，你们只做了前者。

| 学什么 | 资源 | 要跑出什么 |
|---|---|---|
| 可采纳性与一致性 | [A\* 原始论文](https://www.cs.auckland.ac.nz/courses/compsci709s2c/resources/Mike.d/astarNilsson.pdf) | 能证明你们的 Haversine 启发式可采纳 |
| **地标启发式 ALT** | 搜索 "ALT algorithm landmarks triangle inequality"；NetworkX 的 `astar_path` 作为对照 | 实现 3~8 个地标的 `h(n)`，扩展状态数比 Haversine 再降一截 |
| 先验证再优化 | 你们已有的 `check_heuristic_consistency()` | 对 ALT 也做一致性检查 |

**关键动作**：用你们自己的 `check_heuristic_consistency()` 验证新启发式，
并做**可采纳性实验**（抽样比较 `h(n)` 与真实剩余距离）——**这是作业 1 报告里最值钱的一段**。

### 阶段 2：双向 A\*（作业 2 的 20% 分）

| 学什么 | 资源 | 要跑出什么 |
|---|---|---|
| 双向搜索的正确终止条件 | [RoutingKit `ContractionHierarchyQuery::run()`](../../第三方代码/references/RoutingKit/src/contraction_hierarchy.cpp) | 看懂 `forward_queue.peek().key >= shortest_path_length` 这个判据 |
| 交替扩展 vs 同时扩展 | NetworkX 的 `bidirectional_dijkstra` 实现 | 实现反向图 + 双向 A\*，**结果与 Dijkstra 对拍一致** |
| 有向图的坑 | 你们自己的单行道数据 | 反向图必须单独构建，不能复用正向图 |

**最容易错的地方**：终止条件写成"两个方向访问过同一节点就停"——**那在有向图上会返回次优解**。

### 阶段 3：多路径（作业 3 的 25% 分）

| 学什么 | 资源 | 要跑出什么 |
|---|---|---|
| Yen 算法（K 最短路） | [pgRouting 的 KSP 文档](https://docs.pgrouting.org/latest/en/ksp.html)；NetworkX 的 `shortest_simple_paths` | 实现 Yen，产出 K 条**代价递增**且**互不相同**的路径 |
| 为什么不能"跑多次不同偏好" | 你们自己的真实路网 | 实测：最短和最快在短距离下**经常给出同一条路** |
| 路径差异度量 | 自己定义 | 长度加权重合率 `overlap(r1,r2)` |

### 阶段 4：偏好与多目标（作业 3→4）

| 学什么 | 资源 | 要跑出什么 |
|---|---|---|
| 单位归一化 | [Valhalla dynamic costing 文档](https://valhalla.github.io/valhalla/concepts/costing/dynamic-costing/) | 看它如何用"中位速度"把米折成秒 |
| 硬约束 vs 软惩罚 | 同上 | 你们的 4 种偏好已经是这个模式，扩展到"避开拥堵/风景/充电桩" |
| **TSP 近似**（作业 4） | [OSRM Trip 接口](https://raw.githubusercontent.com/Project-OSRM/osrm-backend/master/docs/python/api.md) | 最近邻 + 2-opt；≤6 个途经点可直接枚举 |

### 2.3 核心学习方法：**对拍驱动**

你们已经有了这个工具链，**要把它用到极致**：

```python
# 每实现一个新算法，立刻和 Dijkstra 对拍
d = plan_route(g, s, t, algorithm="dijkstra", cost_model=m)
x = plan_route(g, s, t, algorithm="新算法",  cost_model=m)
assert abs(d.cost - x.cost) < 1e-9      # 比代价，不是比 edge_ids
```

**做随机对拍**：从最大强连通分量里随机抽几百组起终点，跑一轮。这是抓隐蔽 bug 最有效的办法——
你们那个 55.5% 崩溃率就是这样做出来的。

### 阶段 2：CH 全链路（作业 2 的 25% 分，**最大的一块**）

**主要学习资源就是 RoutingKit**（你们已经下到 `第三方代码/references/RoutingKit/`）。

> 如果某台机器上还没这个目录，先用 `docs/references/参考项目清单.md` 里的命令克隆。
> 本文出现的 `第三方代码/references/...` 都是**本地路径**，离线也能读。

**按这个顺序读**（我在 `docs/references/参考项目清单.md` 里也列过）：

| 顺序 | 文件 | 看什么 | 对应任务 |
|---|---|---|---|
| 1 | `doc/ContractionHierarchy.md` | 整体流程；**"收缩顺序可复用"**那段 | 想清 CH 与动态权重的矛盾 |
| 2 | `src/contraction_hierarchy.cpp` → `estimate_node_importance()` | 节点重要性公式 | 节点重要性排序 |
| 3 | 同文件 → `contract_node()` | 加捷径边、witness search | 节点收缩 |
| 4 | 同文件 → `ContractionHierarchyQuery::run()` | **双向查询的正确终止条件** | CH 查询 |
| 5 | 同文件 → `unpack_forward_arc()` | 捷径用"两条弧"表示、递归解压 | 捷径解压 |
| 6 | `include/routingkit/contraction_hierarchy.h` | `Side` 结构、`rank`/`order` | 数据结构设计 |
| 7 | `include/routingkit/id_queue.h` | 工业级优先队列怎么处理平局 | 你们那个崩溃问题的正规解法 |
| 8 | `doc/CustomizableContractionHierarchy.md` | **只读概念** | CH 与动态权重的长期方案 |

**三个已确认的关键点**（可直接引用）：

1. **收缩顺序可复用**——文档原话：*"two graphs that have similar arcs can have very similar contraction orders"*，并提供 `build_given_order()` / `build_given_rank()`。
2. **双向终止条件**：`forward_queue.peek().key >= shortest_path_length` 且反向同理，**两者都满足才停**。
3. **捷径边不存中间节点列表**，用 `is_shortcut_an_original_arc` + 两条弧 ID 表示。**注意**：`mid_node` 只在内部的 `ContractionHierarchyExtraInfo` 里，公开结构中没有——要做可视化得自己存。

**降级方案**（务必准备）：

| 方案 | 做法 |
|---|---|
| CH-lite | 不做 witness search（捷径变多但结果仍正确） |
| 限 pop 次数 | `max_pop_count` 参数限制 witness search 规模，性能与捷径数的取舍 |
| 兜底 | CH 做不出来就用 ALT（A2 那边会做），报告里诚实说明 |

### 阶段 3：CH 与动态权重的冲突（**必做，作业 2 的隐藏雷**）

CH 的捷径边**固化**权重，交通一改就失效——**而且不是变慢，是给出错误结果**。

**做法**：显式回退 + 标注。

```python
if options.algorithm == "ch" and dynamic_weights_active:
    result.warnings.append("CH_STALE_WEIGHTS_FALLBACK_TO_ASTAR")
    return astar_query(...)
```

这条**在 UI 上要显示出来**——"知道工具的适用边界"比"假装没有边界"更得分。

| 测试盲区意识 | `docs/learning/notes/学习笔记_01_从零读懂内核.md` 第 5 课 | 能回答"我的测试漏了什么" |

**最该学的思维**：你们那个 **55.5% 崩溃率**，是在 **7 个测试全绿**的情况下存在的。
**"测试通过"和"程序正确"是两件事。**

### 阶段 2：可采纳性验证实验（作业 1 的 20% 分，**最值钱**）

**做法**：抽样节点，比较 `h(n)` 与**真实剩余距离**（从该点到终点的实际最短代价），
证明 `h(n) ≤ 真实值`。

```python
# 真实剩余距离 = 从 n 到终点的 Dijkstra 代价
real = plan_route(g, n, target, algorithm="dijkstra", cost_model=m).cost
est  = model.heuristic(g, g.node(n), g.node(target))
assert est <= real + 1e-9     # 可采纳性
```

**产出一张图**：横轴节点序号，纵轴 `h(n)` 和真实剩余距离两条曲线，**前者必须在后者下方**。
这张图直接对应 20% 的评分项。

### 阶段 4：多样性评估（作业 3，25% 分）

"候选路径有明显差异"**必须用数字证明**：

| 指标 | 定义 |
|---|---|
| 长度加权重合率 | `|E(r1) ∩ E(r2)| / min(|E(r1)|, |E(r2)|)`，按长度加权 |
| 走廊差异 | 道路名/等级的 Jaccard 距离 |
| 偏好匹配度 | 如"避开高速"路线中 motorway 里程占比 |
| 事件前后变化率 | 施加拥堵后路线改变的比例 |

# 8. 三个学习方式的建议（比具体项目更重要）

### 8.1 不要"先学完再做"

你们现在的代码**已经能跑了**（51 个测试通过、可视化界面）。所以最好的学习方式是：

> **拿到一个真实任务 → 做不出来 → 再去查资料 → 做完 → 写下来。**

不是"我先看完 RoutingKit 再写 CH"，而是"我先写个最简 CH，跑不对了，去 RoutingKit 找答案"。

### 8.2 用自己的项目当教材

你们仓库里已经有**极好的教材**：

| 教材 | 教什么 |
|---|---|
| `docs/learning/notes/学习笔记_03_修掉两个缺陷.md` | 两个隐蔽缺陷怎么被发现和修复 |
| `docs/learning/notes/学习笔记_04_搜索过程怎么变成动画.md` | 性能测量怎么测错（+4.4% → +10.2% → +84%） |
| `docs/development/SearchTrace接口规格.md` | 接口设计怎么考虑体积（压缩比 0.79x → 1.53x） |
| `docs/development/路径规划模块开发说明.md` | 怎么如实标注已知限制 |

**这些是我踩坑踩出来的，比任何教程都贴近你们的实际情况。**

### 8.3 每个角色都该写一份"我的模块说明"

**从作业 1 开始写**，不要等到作业 4。因为：

- 作业 4 的答辩有 15% 是"**核心函数解释**"；
- 写下来才会发现"哪些地方我其实没懂"；
- 5 个人各写一份，最后拼起来就是设计文档。

**格式直接抄 `docs/development/路径规划模块开发说明.md`**：现状 → 边界 → 已知限制 → 审查重点。
