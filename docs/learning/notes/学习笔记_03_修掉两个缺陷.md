# 第 1 课：缺陷①——一半查询会崩

## ① 先回忆现象

笔记 02 第 5 课，你跑 `real_route.py` 时见过：

```text
TypeError: '<' not supported between instances of '_State' and '_State'
```

## ② 根因：`heapq` 的比较规则

先看**待办清单**里的元素长什么样。打开 `router.py`，把元素放进堆的那一行在 **183 行**：

```python
heappush(queue, (priority, new_cost, next_state))
```

它是个**三元组**。`heapq` 要维护"最小堆"，就必须能**两两比较**元素。Python 比较元组的规则是**从左到右逐个比**：

```text
先比 priority  →  一样大？
再比 new_cost  →  一样大？
再比 _State    →  ✗ 崩了！_State 没定义"怎么比大小"
```

前两项是浮点数，**一旦两条路径的代价完全相同**，比较就会落到第三项 `_State` 上。而 `_State` 是个普通的 `frozen dataclass`：

```python
@dataclass(frozen=True, slots=True)
class _State:
    previous_edge_id: int | None
    node_id: int
```

**它没有定义 `__lt__`**，所以 Python 不知道谁大谁小，直接抛 `TypeError`。

## ③ 为什么假地图没暴露，真实路网却崩一半

笔记 01 那张 4 点假地图，边长是**故意错开的**（1000 米、1300 米），永远不会出现"两条路代价一样"。

真实路网完全不同：

- 同等级道路、同样限速的路段**到处都是**；
- 同一个起终点之间常有**对称的绕行方案**（左边绕、右边绕，距离相同）；
- 于是代价相等成为常态。

**实测崩溃率**（我在 552 节点图上跑 300 组随机查询）：

| 偏好 | 崩溃率 |
|---|---|
| fastest | 57.2% |
| shortest | 52.3% |
| avoid_tolls | 54.2% |
| no_highway | 58.2% |
| **平均** | **55.5%** |

## ④ 修法：给堆元素加一个"排队号"

思路很简单：**只要前两项就一定能分出胜负，第三项就永远不会被比较**。

加一个**自增计数器**，让每个进堆的元素有个唯一序号：

```python
from itertools import count

tie_breaker = count()          # 一个只会往上加的数字发生器

heappush(queue, (priority, new_cost, next(tie_breaker), next_state))
#                                              ↑ 排队号：0, 1, 2, 3, ...
```

现在四个元素：

```text
priority → new_cost → 排队号（唯一，绝不相同）→ _State
                                    ↑
                          比到这里就分出胜负了，永远轮不到 _State
```

**为什么叫 `tie_breaker`（平局打破者）**：它唯一的作用就是在平局时决定"谁先进谁先出"。

**一个额外好处**：现在是**先进先出**，结果是**确定的**。修之前是"堆内部结构决定谁先出"，同样的输入可能给出不同答案。

## ⑤ 停下来自问

> **问**：为什么加个计数器就能避免崩溃？
> **答**：因为计数器的值互不相同，元组比较到第三项就分出胜负，永远不会去比较 `_State`。

> **问**：这对算法结果有影响吗？
> **答**：没有。平局时选哪条都是最优解；计数器只是让选择变得确定。

# 第 2 课：缺陷②——A\* 可能悄悄给你绕远路

## ① 这个比上一个难，先建立直觉

回顾笔记 01 第 4 课：**A\* = Dijkstra + 一个猜测**。

```
Dijkstra：从清单里取"已花代价最小"的     →  g(n)
A*      ：从清单里取"已花代价 + 到终点的估算"最小的  →  g(n) + h(n)
```

`h(n)` 是启发式，它是个**猜测**。**猜测错了，A\* 就会过早放弃真正的最优路径。**

## ② 什么叫"猜错"

关键在于：**猜测必须是"低估"，绝不能"高估"**。

| 情况 | 后果 |
|---|---|
| `h(n)` **低估**（比真实剩余距离小） | ✅ 安全。只是搜得慢一点，结果仍最优 |
| `h(n)` **高估**（比真实剩余距离还大） | ❌ 危险。A* 会以为"这条路不值"，然后放弃它 |

第二个性质叫"**可采纳性**"（admissibility）。但还有一个更严格的性质叫"**一致性**"（consistency）：

```text
对任意一条边 u→v，必须满足：   cost(u→v) + h(v)  ≥  h(u)
```

**一致性比可采纳性更强。** 而且——**A\* 的终止条件只在启发式一致时才保证最优**。

## ③ 你们的启发式隐含了一个前提

看 `costs.py` 的启发式（时间型偏好）：

```python
return straight_m / (self.max_speed_kmh * 1000 / 3600)
#      直线距离  ÷  最高速度
```

它算的是"**如果有一条笔直的、以最高速行驶的路，需要多久**"。这是真实时间的下界——**前提是"每条边的长度不能比两端点的直线距离还短"**。

**现实中这个前提通常成立**（路总是绕着走的）。但**不总是**。

## ④ 反例：我自己构造的图

```python
Node(1, 0.0045234602, 0.0009070060)     # 目标点
Node(2, 0.0077187505, 0.0193188345)     # 另一个点

Edge(2, 2, 1, 50.0, 5.0)                # ← 一条 50 米的边
```

注意 node 2 和 node 1 的坐标——它们**相距约 2 公里**，但有一条 **50 米**的边连着。

**这在真实地图上不可能**（路不可能比直线短），但在这些情况下会出现：

- 手工构造的测试图（比如你们要做"最小反例图"来说明约束）；
- 从别处抽稀、估算得到的边权；
- 数据格式转换时坐标和长度来自不同来源。

## ⑤ 在这张图上，A* 给出绕远 3 倍的路

我实测的结果：

| 算法 | 走的路 | 代价 |
|---|---|---|
| Dijkstra | `edge5 + edge2` | **250 米** ← 最优 |
| **A\*** | `edge4`（直达边） | **800 米** ← 绕了 **3.2 倍** |

而程序返回的 `status` 是 `"ok"`——**它不会告诉你算错了**。

## ⑥ 为什么终止条件失效了

我把搜索过程打印出来了：

```text
pop#0: node=4  g=0.0     f=685.2
       push node=1  g=800.0  h=  0.0  f= 800.0
       push node=2  g=200.0  h=2077.9  f=2277.9   ← 注意这个 h！
pop#1: node=1  g=800.0   → 到达终点，记 best_goal=800.0
pop#2: node=2  f=2277.9  → 判定"2277.9 > 800，不可能更好"，停

真实最优：走 node=2，200 + 50 = 250
```

**问题出在 `h(2) = 2077.9`。** 那是 node 2 到终点的**直线距离**，但图上从 node 2 到终点只有一条 **50 米**的边。

于是 A\* 算出的 `f` 是 `200 + 2077.9 = 2277.9`，它以为"走这条路要 2277.9"，实际上只要 250。

**所以 A\* 果断放弃了正确的那条路，选了那条 800 米的直达边。**

> **一句话**：`h` 高估了 41 倍，把最优路径"吓跑"了。

## ⑦ 停下来自问

> **问**：A* 是不是"有 bug"？
> **答**：算法实现是对的。是**这张图的数据违反了 A\* 最优性的前提**（边权与坐标不自洽）。

> **问**：为什么你们真实的路网没出问题？
> **答**：因为 OSM 的边长是**沿真实折线算的**，一定 ≥ 端点直线距离，前提成立。下面第 4 课有实测证据。

## ② 改动一：堆元素加计数器

```python

...
heappush(queue, (priority, new_cost, next(tie_breaker), next_state))
```

## ③ 改动二：终止条件

**改之前**（遇到终点就停）：

```python
if state.node_id == target:
    final_state = state
    break                      # ← 立刻停
```

**改之后**（只在"不可能更好"时才停）：

```python
if priority > best_goal_cost:
    break                      # ← 队列里的最优优先级都超过已知终点代价了，才停

if state.node_id == target:
    if current_cost < best_goal_cost:      # ← 只记更好的，不被更差的覆盖
        final_state = state
        best_goal_cost = current_cost
    continue                               # ← 继续搜，看还有没有更优的
```

**这个改进对真实数据有实际好处**：即使启发式在某处不够准，只要还存在可能更优的路径，搜索就会继续。

## ④ 改动三：一致性校验器（最重要）

**这才是让 A\* 真正可用的东西。**

```python
violations = check_heuristic_consistency(graph)
if violations:
    print("警告：这张图的数据不自洽，A* 的最优性无法保证")
```

它逐边检查 `cost(u→v) ≥ h(u)`（因为以边的终点为目标时 `h(终点)=0`，一致性条件就化简成这样）。

**实测效果**——在我构造的反例图上：

```text
发现 3 处违反一致性的边：
  e2 (到终点 1): h 高估了 21.5 米，而这条边只有 50.0 米
  e3 (到终点 0): h 高估了  9.8 米，而这条边只有 50.0 米
  e5 (到终点 2): h 高估了 23.7 米，而这条边只有 200.0 米
```

**它让我从"怀疑 A\* 有问题"变成"这张图有问题"**——这才是正确的诊断。

# 第 5 课：一个必须知道的测试陷阱

## ① 你们原有的测试比较错了东西

`tests/test_router.py` 里原来有这么一行（在那个测试的第 15 行，改完后移到了 18–19 行）：

```python
self.assertEqual(dijkstra.edge_ids, astar.edge_ids)   # ← 比较"边序列完全相同"
```

**这条断言会误报失败。**

## ② 实测证据

修完崩溃之后，我在等权菱形图上跑：

```text
dijkstra  代价=2000.0  边=[1, 3]
astar     代价=2000.0  边=[2, 4]      ← 同样的代价，不同的路径！
```

上下两条路**完全等价**（都是 1000+1000 米），所以：

- Dijkstra 选了下路；
- A* 选了上路（它的启发式把 `4号节点` 拉得更近）；
- **两条都是最优解**。

但 `edge_ids` 不相等 → 旧断言会红。

## ③ 正确写法：比代价

```python
self.assertAlmostEqual(dijkstra.cost, astar.cost)          # ✅ 比代价
self.assertAlmostEqual(dijkstra.distance_m, astar.distance_m)
```

**为什么比代价才对**：因为作业要求是"**路径最优**"，而"最优"的定义是**代价最小**，不是"走同一串边"。

参考项目 RoutingKit 的文档里明确写着：

> *"It is undefined, what path is chosen when shortest paths are not unique."*
> （最短路径不唯一时，选哪条是未定义的）

**我已经把 `test_router.py` 改好了。**

## ④ 停下来自问

> **问**：两条代价相同的路径，算不算"算法不一致"？
> **答**：不算。都是最优解。只有**代价不同**才是真问题。
