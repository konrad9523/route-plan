## 1. 当前版本目标

当前代码是一个**不依赖第三方库的规划内核** + **一层可选的服务与可视化**：

```text
真实 OSM 路网（GraphML）
  → osm_loader 读成 Graph
  → 代价模型（4 种偏好）
  → Dijkstra / A*（可记录搜索过程）
  → RouteResult（边序列 / 几何 / 统计）
  → FastAPI → Leaflet 页面（搜索过程动画）
```

**核心包 `path_planning` 零第三方依赖**，只用 Python 标准库（`heapq`、`dataclasses`、`xml.etree`、`math`）。
这样每个人可以先读懂搜索代码，再通过适配层接入真实数据。

只有 `api/` 需要 FastAPI；`web/` 是纯前端，**不 import 任何 Python**。

## 3. 运行

在工作区根目录执行：

```powershell
# 全部测试（应 51 个通过）
python -m unittest discover -s tests -v

# 4 节点假地图演示（打印 3 行 JSON）
python -m path_planning.demo

# 启动可视化服务，然后浏览器打开 http://127.0.0.1:8077
python -m uvicorn api.main:app --port 8077
```

`demo` 会分别打印 fastest、shortest 和 no_highway 三种结果。正常情况下：

- fastest 选择高速边；
- shortest 选择普通道路；
- no_highway 强制避开 motorway/trunk。

## 4. 为什么搜索状态包含上一条边

普通最短路可以把 node 作为状态，但转向限制需要知道"从哪条边进入当前节点"。因此代码使用：

```text
state = (previous_edge_id, current_node_id)
```

这样才能表达：

- 禁止左转；
- 掉头惩罚；
- 路口不同入口对应不同转向成本；
- 复杂 OSM restriction Relation。

代价是状态数从"节点数"变成"边数"级别，**换来的是转向约束的正确性**。

## 5. 当前代码的边界

### 已经支持

- 有向边、道路长度与限速；
- 4 种偏好：`fastest` / `shortest` / `avoid_tolls` / `no_highway`；
- 转向惩罚与禁止转向；
- Dijkstra 与 A*（优先队列，等代价平局稳定）；
- 真实 OSM 路网加载（GraphML，含 WKT 几何解析）；
- 搜索过程记录（已访问 / 边界 / 最终路径），可降采样、可序列化；
- GeoJSON 路线结果；
- 显式的无路异常；
- HTTP 接口 + 浏览器可视化。

### 单位约定（**容易踩坑**）

- `shortest` 模式的 `cost` 单位是**米**；
- `fastest` / `no_highway` / `avoid_tolls` 的 `cost` 单位是**秒**；
- `RouteResult.duration_s` **始终是秒**（含转向惩罚），可以跨偏好比较；
- **不要把不同 preference 的 `cost` 直接横向比较。**

### 尚未支持

- 经纬度起终点到道路边的**投影吸附**（现在只能用节点 ID 起终点）；
- **双向 A\*、ALT、CH/MLD**（作业 2 的内容）；
- 动态交通与时间依赖权重（作业 3）；
- 多路径规划（作业 3）；
- `graph_meta.json` 图版本元数据（接口协议里要求，尚未生成）；
- PDF/XML 以外的原始 OSM PBF 解析（现在走 GraphML）；
- HMM 地图匹配、偏航重规划。

## 6. 两个已修复的核心缺陷（**不要回退**）

这两处改动都有回归测试守着，**改 `router.py` 的搜索循环后必须重跑测试**。

| 缺陷 | 症状 | 修法 |
|---|---|---|
| 优先队列等代价崩溃 | 真实路网 **55.5%** 的查询抛 `TypeError` | 堆元素加单调递增平局标识符（`tie_breaker`） |
| A* 终止条件 | 几何不自洽的图返回**次优路径**且不报错 | 改为"队列最优优先级无法改进已知终点代价时才停"；并新增 `check_heuristic_consistency()` |

前者曾经很难发现——`demo.py` 那张假地图的边权是故意错开的，永远不会触发平局。**真实路网上一半查询会崩。**

详见 `docs/学习笔记_03_修掉两个缺陷.md`。

## 8. 代码审查重点

- 启发式是否高估真实代价？（用 `check_heuristic_consistency()` 检查）
- 禁止转向是否被绕过？
- 允许模式、封闭边和收费策略是否被统一处理？
- 路径回溯的 `edge_ids`、`node_ids`、`geometry` 是否一致？
- **A\* 和 Dijkstra 是否在同一 `CostModel` 下对拍？**（注意比较 **cost**，不是 `edge_ids`——等代价时两条路都是最优）
- 不可达和非法请求是否返回明确错误？
- 规划耗时、扩展状态数和队列操作数是否被记录？

## 9. 已知限制（诚实标注）

| 限制 | 说明 | 应对 |
|---|---|---|
| 纯 Python 性能 | 百万节点单次查询预计百毫秒到秒级（**推算，未实测**） | 先做 CSR + CH；性能目标改三档，如实报告 |
| 大图 trace 体积 | 10 万节点不降采样约 7 MB（**推算**） | API 默认 `max_steps=600`，前端走降采样 |
| 起终点只能选节点 | 没有吸附到边的能力，用户点不到"路中间" | 前端吸附最近路口；作业 4 再考虑边内吸附 |
| `geometry` 覆盖约 52% | 552 节点图里 731/1400 条边有几何，其余用路口坐标兜底 | 已知，不影响距离与时间 |
